# 上游渠道接入

厂商预设用于填写协议、API 根地址和配置提示。模型权限与实际调用能力取决于上游账号，预设不代表已完成真实调用验证。

## 新建

1. 在“上游渠道”新增渠道，选择厂商及协议配置档。
2. 填写名称和 API Key，检查 API 根地址；可修改为自己的中转地址。
3. 点击“获取模型”，选择本次要导入的模型；也可以手动填写模型名。获取列表不会产生生成请求。
4. 保存后，到模型分组中添加这些模型，再通过分组名提供服务。

保存只导入所选模型，不会在保存后自动全量同步。开启自动同步后，定时同步会新增上游以后发现的全部模型；手动同步也是全量新增，已有模型不会被删除。手动模型模式不执行自动发现。

## 地址与预设

Base URL 必须是 API 根地址，包含该服务需要的版本或路径前缀，例如 `http://localhost:1234/v1`。Chat 接入器会在它后面追加 `/chat/completions`。不要填写到具体操作接口，也不要把 Key 放在 URL 中。

通用兼容服务不猜测版本前缀。选择厂商时会保留用户自定义地址；需要替换时显式应用预设。预设更新不会覆盖已保存地址、协议或凭据。

首批包含通用四协议、OpenAI、Anthropic、Gemini、DeepSeek、OpenRouter、SiliconFlow 的配置预设。具体来源链接由后端目录返回。它们只覆盖应用已有的对话协议，不代表支持这些厂商的图片、视频、音频等其他接口。Azure、AWS Bedrock、Vertex AI 等特殊认证尚未接入。

## 编辑

Key 留空保留原密钥；脱敏文本不会被当作新 Key。编辑表单中的“获取模型”和调用验证使用当前草稿，可在后端复用旧 Key，不改变已保存连接。取消编辑不会保存草稿或预览模型。

保存更新只新增所选模型，未勾选既有模型不会删除它们。删除仍是独立操作。修改渠道协议会影响渠道下全部模型及引用它们的分组，请检查引用后操作。

## 三种验证含义

| 操作 | 能证明什么 |
|---|---|
| 检查连接配置 | 本地字段合法，能够解析操作端点 |
| 获取模型 | 模型列表接口成功，不代表有生成权限 |
| 调用验证 | 指定模型在指定响应模式下的一次真实调用成功 |

调用验证由用户主动点击，会消耗上游额度。输出上限默认 32 token，可设为 1–128；输出上限不等于总 token 消耗保证。可选择流式或非流式；每次只调用一个模型，失败不会切换到其他渠道或自动重发。

验证最多执行 25 秒，限制响应大小；超过验证期限不代表正式调用一定失败。模型若需要更高的最小输出预算，本验证可能被拒绝，不能据此判定渠道完全不可用。诊断区分请求、上游 HTTP、响应处理、取消和超时；不返回原始密钥或上游响应正文。验证数据不写入正常调用日志或正式熔断状态。

## 余额与额度查询

连接地址、生成凭据和查询来源分别配置。厂商预设不自动启用余额查询，也不会因为渠道采用 OpenAI 兼容协议就自动识别余额接口。在卡片“查询余额”或已有摘要的设置入口管理查询来源（每个渠道一个）；内置账户适配、自定义请求、保存与刷新规则见[余额与额度说明](channel-quota.md)。

## 管理 API

### 渠道图标

新建或编辑渠道时，点击“渠道图标”可搜索内置品牌或上传 PNG、JPEG、WebP、SVG（最大 2 MB、源图片宽高最大 4096 像素）。选择“自动跟随厂商”可清除手动设置。修改只在保存渠道后生效，渠道卡片与模型列表共用此图标。

展示顺序为手动图标、`provider_id` 对应的品牌、协议图标兜底，品牌与出站协议相互独立。旧渠道无需重新配置；未知内置名称或损坏图片会回退显示。

渠道 CRUD 支持 `icon` 字符串：内置图标保存名称，上传图片在前端转换成 96×96 PNG data URI。后端限制 data URI 长度为 64 KiB、PNG 宽高不超过 256 像素，并完整解码验证。更新时省略 `icon` 保留原值，空字符串恢复自动；此字段不参与连接解析、模型发现或调用验证。

### 连接与模型

新增 `GET /api/upstream-presets`、`POST /api/channels/resolve` 和 `POST /api/channels/test`，扩展原模型预览与渠道 CRUD。它们与其他管理 API 一样仅接受本机管理访问。

创建与更新可带 `models: ["模型名"]`，只做去重后的新增导入；空数组表示本次不新增，省略保持旧调用方语义。渠道和模型在同一事务中保存，失败整体回滚。预览、解析和测试可带 `channel_id` 并省略 `key`，由后端继承已保存凭据，再应用显式草稿字段。

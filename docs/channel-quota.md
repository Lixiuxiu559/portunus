# 渠道余额与额度查询

本文对应当前工作区源码，不代表所有已发布安装包均包含这些功能。余额基础能力验证使用本地模拟与隔离界面；2026-10-27 另使用用户授权的 NewAPI 账号只读验证钱包、5 份订阅及后端汇总，并在隔离组件页面检查卡片与详情。该结果不代表所有 NewAPI 版本和站点均已验证。

## 入口与保存

从顶部导航进入“上游渠道”。未配置时点击卡片“查询余额”；已有摘要时，点击设置图标打开“余额与额度”面板。每个渠道只配置一个查询来源；来源类型与生成接口协议独立选择，不通过域名自动判断。

1. 选择适配器，填写查询地址及所需凭据。
2. 点击“测试草稿”核对账户、单位和返回字段。它会发送一次只读上游查询，不保存配置或余额；修改草稿后，旧测试结果失效。
3. 查询默认不启用，自动刷新为 0（关闭）。“保存”仅保存当前启用状态、间隔和配置；“保存并查询”会启用查询、按表单间隔保存并立即查询一次。
4. 需要定时查询时，启用来源并把间隔设为 1–60 分钟后点“保存”。关闭面板或切换页面不会关闭后端调度；关闭定时查询请设为 0，完全停用请取消“启用查询”。

“保存”本身不发查询，但已启用的后台调度仍可按计划执行。打开列表、搜索或详情只读取本地缓存；卡片刷新图标和详情“立即查询”才发起主动查询。测试与查询不会发送模型生成请求。

渠道级 1:1：同一渠道已有查询来源时，再次创建会被拒绝（409），只能编辑现有配置。升级旧版本时若存在多个来源，保留最近成功查询的一条；都没有成功记录时保留最近更新的一条，其余来源及其状态删除。渠道就是一个上游账户，多账户应分别建立渠道。

## 支持的来源

| 来源 | 凭据 | 查询口径 |
|---|---|---|
| DeepSeek | 渠道 Key 或独立 Key | 官方账户余额，按返回币种分别展示 |
| 硅基流动中国站 | 渠道 Key 或独立 Key | 官方 `totalBalance`，不推断国际站 |
| OpenRouter | 独立 Management Key | 账户 credits 减去 usage；此适配器要求专用查询凭据，不继承渠道生成 Key |
| 自定义余额 / 额度 | 渠道 Key、独立 Token 或无鉴权 | 自定义请求和 JSON Pointer 字段映射 |
| NewAPI | 独立账户 Access Token、User ID | 钱包 quota / used_quota、各份生效订阅及计费偏好；模型调用令牌不等于账户 Token |

DeepSeek、硅基流动中国站和 OpenRouter 内置适配器只允许各自固定官方查询根地址，不随渠道推理地址变化。第三方兼容站点使用 NewAPI 账户适配器或自定义来源；不要把官方查询 Token 发送给未核实的站点。

NewAPI 查询地址填写站点 API 根地址，可包含部署前缀，不追加 `/api/user/self`。不同站点的单位可能不同，默认显示原始 QUOTA。仅在确认站点换算规则后填写每单位 quota 和显示单位；详情同时保留原始额度，避免把默认倍率当作真实余额。

NewAPI 一次查询分别读取 `/api/user/self` 和 `/api/subscription/self`；存在生效订阅时额外读取 `/api/subscription/plans` 获取名称。钱包和订阅可以同时存在，钱包为 0 不代表没有订阅额度。卡片仅展示钱包与生效订阅剩余的整体合计，通过余额区域右上角按钮分别查看钱包、计费偏好及每份订阅的本期总额、已用、剩余、重置和到期时间。整体合计由后端先累加原始 QUOTA 再换算；部分额度接口失败时明确提示“合计不完整”，不把缺失项当成已确认的零。同套餐的多份订阅独立保留；订阅汇总由后端先相加原始额度再换算，不包含钱包。含不限额订阅时明确标注，不给出有限合计。订阅到期后提示刷新汇总；旧缓存没有汇总字段时也需刷新获取。

NewAPI 卡片上的金额保留两位小数，正数不足 0.01 时显示 `<0.01`，负数绝对值不足 0.01 时显示 `>-0.01`，真实零显示 `0.00`。舍入仅影响卡片排版，详情保留后端返回的完整金额精度及原始 QUOTA；原始额度、credits 等非金额单位不套用两位小数规则。

钱包、订阅和套餐名称查询分别记录成功或失败；局部失败保留本次成功部分，查询失败不表示没有订阅。任一接口限流时，整个来源遵守冷却时间（多个接口取最长等待时间，未提供时为 60 秒，上限 1 小时），冷却期间不能再次主动查询，自动调度也不会提前请求。套餐名称读取失败仍保留额度并使用套餐编号展示。实际扣费顺序由站点计费偏好及套餐规则决定，汇总不保证每个模型请求都可用。

留空 Token 表示保留同一适配器的既有凭据，勾选清除才会清除。切换适配器会清除旧凭据，需要明确填写新凭据。读取接口只返回是否已配置，不返回 Token。

## 卡片、时间与失败状态

卡片突出金额与单位，并显示相对查询时间；悬停时间可查看完整的本地查询成功时间。单来源金额摘要通常显示“账户余额”或“可用额度”。卡片最多展示两项条目，更多条目可进入详情查看。不同账户或币种不会相加；未知值显示“未知”，0 保留为 0，明确无限显示“无限”。

| 状态 | 展示与处理 |
|---|---|
| 正常成功，尚未再次查询 | 保留上次查询值及时间；放置较久不表示余额或账户过期，也不表示实时余额 |
| 刷新中 | 刷新按钮转圈并禁用重复操作；已有可展示的查询值继续显示 |
| 临时失败、限流等，仍可使用旧快照 | 在失败保留窗口内显示旧金额及“更新失败”等提示；成功时间不被失败时间替换 |
| 查询失败且旧值超出保留窗口 | 主摘要隐藏旧金额，显示失败提示；详情可查看历史查询记录，不能当作当前可用额度 |
| 凭据无效、无查询权限、查询配置无效 | 旧身份余额立即停止作为当前值展示；修正后需要一次成功查询，后续网络错误不能使旧值恢复 |
| 来源停用、配置或继承 Key 变化 | 停用来源不再查询；发生有效配置／身份变化时作废旧当前结果，迟到响应不能覆盖新版本 |
| 尚未查询 | 显示尚未查询；来源启用后可主动查询 |

技术上的“新鲜期”：自动刷新关闭时为 5 分钟，开启时采用配置间隔。只有查询失败后的旧值展示才受最长年龄约束：`max(10 分钟, 2 × 新鲜期)`，从**上次成功时间**起算，不是从失败时重新给满一个窗口。正常成功值超过这个年龄仍可显示，用户取消也不按上游失败处理。

刷新同一来源不会重复发送；查询执行失败不在当前请求中自动重发。上游限流时显示冷却信息，冷却结束前不能再次查询；启用自动刷新后由后台调度安排后续尝试，默认关闭时不会因失败自行开启。配置修改、禁用、删除或继承渠道 Key 变更会取消并隔离旧查询。删除查询来源会删除该来源配置和最新状态，不删除渠道或模型；“历史查询记录”只指保留的上次快照，不是可追溯的查询流水或余额历史曲线。

结果用于观测，不参与路由、熔断、计费或跨账户余额合计。Sub2API Key 限额及厂商套餐适配已取消；OAuth 与自定义脚本未实施。


## 自定义查询

选择“自定义余额 / 额度”，填写查询根地址（例如 `https://example.com`）和站内路径（例如 `/api/balance`）。路径会接在根地址后，根地址可带部署前缀。敏感凭据放在专用 Token 中，或明确选择继承渠道 Key；请求头用 `{{token}}` 引用。无需凭据的接口选择“无鉴权”。更改根地址后，旧独立 Token 不会发送到新目标，需重新填写。

例如接口返回：

```json
{"success":true,"data":{"balance":"12.34","used":"5.00"}}
```

配置剩余路径 `/data/balance`、已用路径 `/data/used`，明确填写显示单位（例如 CNY）。若需要检查业务状态，勾选成功条件，填写 `/success` 等于 `true`。比较值是 JSON 标量原文，例如 `true`、`null`、`200` 或 `"ok"`，保留类型和大数精度。

可以添加 1–20 项分别展示多个钱包；每项使用稳定且唯一的 ID。字段路径采用 JSON Pointer，数组首项为 `/wallets/0/balance`，字段名中的 `/` 写作 `~1`、`~` 写作 `~0`。可选按“总额度减已用额度”计算剩余；可选填写正数换算除数和原始单位，详情会保留原始值。界面不会猜测币种或默认倍率。

仅配置只读查询接口。GET 不接受请求体；POST 只支持 JSON，请求体上限16KiB。不能配置重定向、跨站路径或传输控制头，不在路径、普通请求头或请求体中填明文密钥。Token 占位符仅支持请求头；常见认证请求头中的凭据必须写成占位符。

可选“无限条件”仅在上游明确提供标志时使用；数字支持 JSON 数字或十进制字符串，后端按精确十进制处理。缺失字段不能自动补 0，字段路径与业务成功条件应先通过“测试草稿”核对。

这项能力采用结构化配置，不直接执行 CC Switch 的 JavaScript 提取函数。暂不支持多次请求串联、登录、签名计算、OAuth 刷新或任意表达式。


## 管理 API 与维护边界

以下路径均位于 `/api`，沿用本机管理访问限制，不向 `/v1` 暴露余额：

| 方法与路径 | 用途 |
|---|---|
| `GET /quota/adapters` | 适配器、凭据模式和字段描述 |
| `GET /channels/:id/quota-sources` | 读取某渠道的配置与最新状态，凭据仅返回是否存在 |
| `POST /channels/:id/quota-sources` | 创建来源，不主动查询；渠道已有来源时返回 409，需改用 PUT 编辑 |
| `PUT /quota-sources/:id` | 更新来源，提交 `expected_revision`；版本冲突返回 409 |
| `DELETE /quota-sources/:id` | 删除来源及最新状态 |
| `POST /quota-sources/preview` | 测试草稿；不落配置或快照 |
| `POST /quota-sources/:id/refresh` | 主动查询一次；已有任务返回 202，不重复查询 |
| `GET /quota/summaries?channel_ids=1,2` | 批量读取缓存，单次最多 100 个渠道 ID |

已执行的上游查询无论成功还是失败，均用 200 返回统一状态视图；上游 HTTP 状态位于 `failure`，与本机 API 的 400/404/409/429 配置、归属、冲突或并发限制区分。202 表示任务进行中，后续读取缓存获取终态，不能不断 POST 轮询。

后端 `quota` 统一配置版本、来源互斥、执行、结果归一化与调度，适配器只构造请求和解析响应；前端摘要／草稿 hooks 管理取消与迟到响应，展示组件不计算金额或匹配厂商响应。默认单次 HTTP 超时 15 秒、查询期限 20 秒、响应上限 1 MiB，禁止重定向，单来源一次在途查询、全局最多两次。

渠道卡片统一使用 `QuotaCardBalance` 展示金额、单位和查询时间。`quotaCardModel` 将后端标准条目或 NewAPI 账户总额适配为相同的展示数据；金额精度由通用 `quotaAmount` 处理，单位始终独立排版。卡片组件不包含厂商分支，不在浏览器中计算余额或跨币种合计；详情继续保留各查询来源的完整信息。

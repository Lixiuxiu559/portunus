# 渠道余额与额度查询

在“上游渠道”的余额面板中添加查询来源。一个渠道可有多个来源；来源类型与生成接口协议独立选择，不通过域名自动判断。

1. 选择适配器，填写查询地址及所需凭据。
2. 使用预览核对返回的账户、单位和额度；预览不保存配置或余额。
3. 普通保存只保存配置；“保存并查询”启用来源并查询一次。
4. 自动刷新默认关闭，启用后按设定间隔查询。打开列表和详情只读取缓存。

| 来源 | 凭据 | 查询口径 |
|---|---|---|
| DeepSeek | 渠道 Key 或独立 Key | 官方账户余额，按返回币种分别展示 |
| 硅基流动中国站 | 渠道 Key 或独立 Key | 官方 `totalBalance`，不推断国际站 |
| OpenRouter | 独立 Management Key | 账户 credits 减去 usage；生成 API Key 不足以查询此接口 |
| 自定义余额 / 额度 | 渠道 Key、独立 Token 或无鉴权 | 自定义请求和 JSON Pointer 字段映射 |
| NewAPI | 独立账户 Access Token、User ID | 账户 quota / used_quota；模型调用令牌不等于账户 Token |

NewAPI 查询地址填写站点 API 根地址，可包含部署前缀，不追加 `/api/user/self`。不同站点的单位可能不同，默认显示原始 QUOTA。仅在确认站点换算规则后填写每单位 quota 和显示单位；详情同时保留原始额度，避免把默认倍率当作真实余额。

留空 Token 表示保留同一适配器的既有凭据，勾选清除才会清除。切换适配器会清除旧凭据，需要明确填写新凭据。读取接口只返回是否已配置，不返回 Token。

刷新中的重复操作不会重复发送；配置修改、禁用、删除或渠道 Key 变更会取消旧查询并作废旧结果。正常成功的上次余额会保留，并标明实际查询时间；放置较久不代表余额或账户过期。可在卡片直接刷新，时间悬停显示完整时间。鉴权失败后旧余额不再展示；临时失败时可能保留上次查询值，失败保留窗口超时后隐藏金额，原因与历史记录可在详情查看。未知值不会显示成 0。

结果用于观测，不参与路由、熔断、计费或跨来源余额合计。Sub2API Key 限额及厂商套餐适配已取消；OAuth 与自定义脚本未实施。


## 自定义查询

选择“自定义余额 / 额度”，填写查询根地址（例如 `https://example.com`）和站内路径（例如 `/api/balance`）。路径会接在根地址后，根地址可带部署前缀。敏感凭据放在专用 Token 中，或明确选择继承渠道 Key；请求头用 `{{token}}` 引用。无需凭据的接口选择“无鉴权”。更改根地址后，旧独立 Token 不会发送到新目标，需重新填写。

例如接口返回：

```json
{"success":true,"data":{"balance":"12.34","used":"5.00"}}
```

配置剩余路径 `/data/balance`、已用路径 `/data/used`，明确填写显示单位（例如 CNY）。若需要检查业务状态，勾选成功条件，填写 `/success` 等于 `true`。比较值是 JSON 标量原文，例如 `true`、`null`、`200` 或 `"ok"`，保留类型和大数精度。

可以添加多项分别展示多个钱包。字段路径采用 JSON Pointer，数组首项为 `/wallets/0/balance`，字段名中的 `/` 写作 `~1`、`~` 写作 `~0`。可选按“总额度减已用额度”计算剩余；可选填写正数换算除数和原始单位，详情会保留原始值。界面不会猜测币种或默认倍率。

仅配置只读查询接口。GET 不接受请求体；POST 只支持 JSON，请求体上限16KiB。不能配置重定向、跨站路径或传输控制头，不在路径、普通请求头或请求体中填明文密钥。Token 占位符仅支持请求头；常见认证请求头中的凭据必须写成占位符。

这项能力采用结构化配置，不直接执行 CC Switch 的 JavaScript 提取函数。暂不支持多次请求串联、登录、签名计算、OAuth 刷新或任意表达式。

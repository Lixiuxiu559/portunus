# 协议兼容检查统一为诊断模式

## 当前行为

删除 `proxy.conversion_policy`、`PORTUNUS_PROXY_CONVERSION_POLICY`、协议装配的 Policy 参数和 strict/legacy 策略类型，同时删除原生兼容性错误、续接来源未验证错误及网关对应拒绝/排除分支。配置文件里的旧字段和旧环境变量不再生效，像其他未知配置一样被忽略；新配置序列化不输出策略字段。

`RequestEnvelope` 继续保存原始请求及有位置的片段，访问器保持深复制。同协议仍保留未知字段、原生工具、签名/密文和续接引用，必要字段仍按 RawMessage 改写；跨协议沿用现有语义映射和降级。`PrepareTarget` 继续返回 `ComposeStats.Compatibility`：checked、scope、compatible 和 issues 都保留。发现降级、未知原生构造或来源未验证只记录诊断，不据此拒绝请求或跳过当前目标。

这不承诺所有字段跨协议无损，也不证明原生签名/续接引用来源可信或目标模型支持该能力。正常 JSON/协议输入验证、显式思考参数转换错误等现有功能错误继续返回，未因移除 strict 而放宽。

## 始终生效的安全边界

以下规则独立于兼容诊断，继续强制执行：

- 完整 SSE 读取、单帧和预提交缓存上限、终态识别；缺终态不伪造正常完成。
- 首次交付开始后禁止重试/换家，短写和 Flush 失败不例外。
- 可能执行原生操作或状态续接的请求，发送后即使未交付，也禁止自动重放。
- 请求级显式 HTTP 总尝试预算，兼容重试也扣次数；跨目标累计首内容期限、客户端取消和现有 idle 超时。

删除请求侧兼容拒绝，不能改成自动剥离安全标志，不能让不兼容的诊断自动释放尝试次数，也不改变路由顺序。

## 诊断与历史兼容

日志继续保存检查范围和检查摘要及既有桥接/降级计数，不保存原生正文。退役的 `logs.conversion_policy` 数据库列保留历史值，新日志该值为空；API JSON 不再输出该字段。既有 token、缓存、交付状态及独立 HTTP attempt 口径不变。

原生 JSON Schema 的 `strict` 字段属于供应商工具/结构化输出参数，与本次删除的网关转换开关无关，继续保留。

## 验证范围

覆盖旧 JSON/env 策略值被忽略且不再输出配置、诊断报告不触发请求拒绝或跳目标、同协议原生续接保留、续接流失败仍禁止重放、历史日志策略值保留且不暴露、报告不包含敏感原生值。已有 SSE、资源限制、交付控制、总预算与 deadline 回归继续执行。

实际执行 `go test ./...`、`go vet ./...`、`go test -race ./backend/gateway ./backend/protocol ./backend/shared` 均通过，`git diff --check` 通过。Correctness、Standards 和 Spec 审查无剩余问题；配置部分复核由实现者参与，独立性降级。未安装或运行项目未配置的复杂度/突变工具；本次主要删除分支，以差异审查、功能回归和竞态检测验证。未重启正式服务。

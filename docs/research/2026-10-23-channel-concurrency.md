# 可选渠道并发上限

## 需求与默认行为

用户要求：“做可选渠道并发上限，满载时故障转移按固定主备顺序走备用，手动模式不自动切换，默认保持现有调用兼容，不为准入拒绝制造 HTTP attempt，安全边界继续强制执行。”

渠道新增 `max_concurrent_requests`，合法范围0至9007199254740991（前后端均可精确表示的非负整数），默认0表示不限制。历史行迁移为0，旧创建请求缺失字段仍为0，更新缺失保留已有值、显式0关闭限制；负值及非法类型拒绝。创建/编辑渠道表单提供该设置，预设及连接变更不会覆盖它。保存与所选模型导入仍在原事务内，失败整体回滚。

限制范围是同一网关进程内 `/v1` 生成调用，按channel ID跨模型、跨分组共享；多个进程不会共享计数，同一上游账户配置成不同渠道也不会合并配额。模型发现、余额查询和管理端主动调用验证保持既有独立行为，本阶段不把它们纳入生产生成并发计数。该能力不是RPM/TPM配额，也不提供排队或后台重试。

## 固定路由

- manual仍只使用激活成员；满载返回503，不切备用。
- failover仍按priority、成员ID固定排序，满载直接顺延，不在满载目标上重试或等待名额。
- 若所有候选均因并发满载或熔断被跳过，未进行relay时返回503；存在限流冷却且所有候选不可用时，沿用已有429冷却优先级。
- 真实HTTP Do仍受统一预算控制。跳过、准入竞争失败及等待前预检查不扣HTTP预算、不生成HTTP attempt；不会因候选多而放大可发送次数。
- 满载是本地 `channel_capacity`，不是供应商429或健康故障，不增加失败计数、不算恢复成功。Retry-After:1只是建议稍后重试，不代表名额届时一定释放。

## 原子准入与名额生命周期

外层候选检查先保留既有控制、冷却和熔断检查，再对渠道容量作无占用预览。实际发送处在资源/取消/累计期限/剩余预算、限流、可取消退避及退避后复查完成后，原子取得渠道名额，再取得或复用breaker令牌、reserve预算、trace.begin、HTTP Do。预览与实际准入之间即使有并发竞争，也不能超出正数上限。

名额按整个relay持有，覆盖等头、非流式完整body读取与转换、流式终态和交付以及顺序预算字段兼容Do。兼容重试复用同一名额，第一条错误响应body关闭不提前释放。普通失败重试则结束前一个relay、释放后重新准入；首次Do前的退避不占名额。

正常结束、错误、取消、资源或控制限制终止均经defer释放。响应body关闭和watchdog停止在释放之前，最终AttemptWrite/LogWrite/RoutingWrite在释放之后；兼容重试中间观测仍属于未结束relay，继续持有。渠道取得名额后若breaker忙或reserve失败，仍会释放，不制造Do。满载拒绝发生在breaker Acquire之前，不会抢占或改变半开恢复名额。

名额无固定TTL，不因时钟推进提前允许重叠；继续由既有累计deadline、stream idle及取消控制调用生命周期。正常持续输出的长流会一直占用名额。

## 配置变更和内存边界

计数只按channel ID建立一个桶，不按连接指纹、模型、分组或limit分桶。默认不限的调用也计数，因此后续新请求启用或降低上限时会看到已有占用；更换Key、URL、协议等连接配置不会清空在途计数。升高或关闭上限同样复用原桶。Release在锁内幂等，旧名额重复释放不会扣减新请求占用。

上限随 `router.Resolve` 的渠道配置快照用于该请求；修改生效于随后解析的请求，不杀掉已有调用，也不向已完成选路的旧请求强制推送配置。降低上限后已有调用可以超过新值，待其逐个结束后再放新请求；这不等于强制中止以达成瞬间限额。

只保留在途数大于0的桶，最后一个名额释放后删除；不保留无限增长的历史渠道条目，不启动后台清理任务。

## 安全与诊断

资源限额、统一总尝试预算、跨目标累计deadline、取消、429作用域冷却、半开单探测、SSE预提交/终态校验和交付后禁止重放保持原有强制裁决。

原生操作在实际发送后仍禁止自动重放。本地容量竞争拒绝且尚未取得名额时，可以证明当前relay未发送，选择后续候选属于初次准入，不是重放；此处不误用原生操作重放限制阻止固定故障转移。已发送后发生的失败不适用该例外。

切换诊断增加 `capacity_acquired` / `capacity_released`，满载候选记录candidate_skipped，发送前原子准入拒绝记录admission_blocked。`capacity_limit` / `in_flight`保存事件发生时的上限和占用快照，零值明确输出；不是当前实时监控数值。旧诊断缺字段保持未采集，不猜测为0。默认0时仍正常记录名额生命周期和“不限”状态。

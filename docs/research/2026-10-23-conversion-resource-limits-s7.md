# 转换链资源限额（S7）

## 覆盖范围与配置

请求入口在读取前检查 Content-Length；未知长度或分块请求最多读取限额加 1 字节。所有生成上游的非流式响应体都走相同有界读取，包括成功响应、错误响应和预算兼容重试的错误检测体。转换后的上行请求和非流式响应再次检查，防止模型改写、协议编码或兼容参数改写使结果越界。

`proxy.resource_limits` 使用以下字段。默认值是本阶段可调整的保护值，不代表经过生产请求尺寸统计得出的容量承诺。

| JSON 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `max_request_bytes` | 33554432（32 MiB） | 客户端请求体及装配后的上行请求体 |
| `max_response_bytes` | 33554432（32 MiB） | 上游非流式/错误体及转换后的非流式响应 |
| `max_native_fragments` | 8192 | 每份原生快照的选定结构片段；流中同时约束候选、工具/输出项及诊断去重状态 |
| `max_tool_arguments_bytes` | 4194304（4 MiB） | 单个工具参数，流式跨帧累计 |
| `max_accumulated_bytes` | 67108864（64 MiB） | 单次请求/响应检查或单个有状态流转换阶段的正文、思考和工具参数累计 |
| `max_json_depth` | 128 | 解析前的 JSON 对象/数组嵌套深度 |

环境变量分别为 `PORTUNUS_PROXY_MAX_REQUEST_BYTES`、`PORTUNUS_PROXY_MAX_RESPONSE_BYTES`、`PORTUNUS_PROXY_MAX_NATIVE_FRAGMENTS`、`PORTUNUS_PROXY_MAX_TOOL_ARGUMENTS_BYTES`、`PORTUNUS_PROXY_MAX_ACCUMULATED_BYTES`、`PORTUNUS_PROXY_MAX_JSON_DEPTH`。字段省略或为 0 时回退默认；配置加载拒绝负值。沿用既有环境覆盖规则：无法解析为整数的环境变量忽略。没有关闭安全检查的开关。

`backend/resource` 只定义通用限额、静态错误与有界读取/深度检查，不依赖业务模块；`protocol` 定义协议路径、原生片段和流式累计；`gateway` 执行读取、调用与失败编排。`shared` 只引用通用契约，不反向依赖协议实现。

## 计量与内存边界

原生捕获先检查 body 大小、嵌套深度，并通过 token 遍历检查选定结构片段、工具参数和已支持的文本路径，再建立 RawMessage 索引和快照。实际追加片段时再次检查数量。工具参数对象不被递归误算成原生片段；Anthropic 工具结果文本/搜索标题与URL、Chat 结构化文本响应及 Gemini 序列化工具结果也计入全文，对象值按原始 JSON 字节计量；自定义工具数据中的任意字段名不被当成协议路径。JSON 数字使用 UseNumber，原生大整数不经 float64 往返。

流式保留既有 1 MiB SSE 单事件上限和预提交 256 KiB/128 事件上限。连续小帧不能绕过工具参数或全文累计检查；检查发生在源累计器和目标生命周期状态写入前。每个有状态转换阶段拥有独立累计预算，同一份语义经过源、目标时不会重复扣同一个共享额度；各阶段仍分别受限。单帧拆成多个语义事件时共享私有不可变原生存储，公开访问器仍返回深拷贝，避免完整原生帧按 part 数量放大。候选、工具和输出项数量也受限，防止大量空字符串绕过字节限额。资源失败保持不可逆，后续 Convert/Finish 不会恢复成功。

同协议 SSE 原始字节继续直接透传，不保存整个流的正文，因此不按整个已传输流的字节数累计 64 MiB；仍检查单事件、原生结构、工具增量、候选及诊断状态。同协议非流式响应检查通过后保持原始字节；请求继续保留既有模型/thinking 改写规则。跨协议保持原有映射与组合优先级，不扩展供应商能力，也不恢复 strict。

这些是逻辑资源限额，不是精确 RSS 配额。JSON token 会分配当前字符串，编码结果在生成后再次检查；输入 body、快照、规范结构、输出及各有状态阶段可能同时保留有界副本。内存不会严格等于某一项配置值；opaque 扩展和媒体由 body/事件大小及深度保护，不承诺所有扩展字段的递归语义累计。同步解析/编码仍不被强行抢占，沿用累计 deadline 结束后的提交裁决。

## 失败与观测

未交付时，请求资源超限返回 413，上游响应或流转换超限返回 502。`failSpec` 统一归为 `resource_limit`，停止整个请求，不普通重试、不换目标、不做额外兼容重试，也不计渠道熔断。已经交付的流只能发送适用的失败帧并结束，不能改写既有 HTTP 状态，不能重放或伪造成功终态；已观察源终态也不能吞掉后续资源错误。

超限不截断工具参数、密文或正文后当作成功。错误和新增日志只包含静态类别及数字，不保存源正文或字段值；既有兼容诊断继续保留。没有实际 Do 的入口拒绝/预检查不产生 HTTP attempt；已收到响应头后超限仍保留真实上游状态码。请求级预算、累计 deadline、取消、退避及原生操作禁止重放继续执行。

## 验证

专项用例覆盖恰好达到上限/超过上限、未知长度/分块读取、有界读取量、JSON 引号转义与深度、大整数、原生片段、四协议工具参数、连续小帧累计、兼容重试、交付前后停止及终态后超限。正常小请求的原生扩展、响应字节和既有调用头保持兼容。

独立三轴评审以 `5823690b71d4ce53aaaf814c6e086144ff409ff7` 为固定基线，包含工作区差异和未跟踪实现/测试。Correctness 发现单帧快照按语义事件复制的放大、工具结果文本漏计；Spec 发现 Chat 结构化文本响应漏计。上述问题已修复，原复现及边界用例复核通过，无剩余 finding；Standards 未发现硬性违规或需报告的维护问题。入口元数据解析前的深度检查另经局部复核。

快照放大复现使用 66,888 字节 Gemini 帧、100 个短文本 part 和较大 opaque 扩展，仍输出 101 个语义帧；修复后观察到总分配从 32,653,984 字节降至 1,439,624 字节。此数值是单个本地复现结果，不是所有请求的性能承诺。公开快照读取隔离测试继续通过。

项目未配置复杂度或突变测试工具，本阶段未安装或运行这些工具，不提供 CRAP 或突变分数。未调用真实供应商，未重启正式服务。

最终执行并通过：`go test ./...`、`go vet ./...`、`go test -race ./backend/gateway ./backend/protocol ./backend/shared ./backend/resource`、`git diff --check`。包括11,000层请求在元数据解码前返回413、预提交失败不泄露缓存、交付后超限无成功终态等新增集成用例。

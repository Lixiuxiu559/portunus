# 非流式累计期限与可取消退避（S6）

## 请求累计期限

非流式使用同一个 `requestControl`，从基本请求解析后、分组选路之前开始计时，所有目标、普通重试、兼容重试和退避共用 `non_stream_timeout_seconds`。默认仍为 600 秒，零值回退默认、负数在配置加载时拒绝。删除每次 relay 独立重建的非流式 timeout，避免切换目标获得新窗口。

期限覆盖连接、响应头、成功及失败响应体、兼容参数检测响应体、完整 body 读取、usage 提取与响应转换。非流式尚未发送给客户端，只有完整响应准备好后才能通过 commit；准备完成与期限到达在同一锁内裁决，过期不能返回已经缓存的正文。同步解析/转换不被强行中途抢占，但结束后必须再次检查期限，超时结果不能提交。

非流式的 commit 表示完整响应已在期限内准备好，随后由调用方写客户端；不证明客户端收到正文，也不承诺客户端慢读时的总传输期限。流式仍在首次交付开始时撤销首内容计时器，之后沿用 idle、客户端取消和有界终态尾部，不以非流式期限截断长流。

## 统一退避入口

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `retry_backoff_base_ms` | 200 | 第一次后续发送的指数上界 |
| `retry_backoff_max_ms` | 2000 | 每次等待的上界封顶 |
| `max_http_attempts` | 沿用 4 | 所有显式 Do 的共同预算 |

新退避字段支持 `PORTUNUS_PROXY_RETRY_BACKOFF_BASE_MS` 和 `PORTUNUS_PROXY_RETRY_BACKOFF_MAX_MS`。零值恢复默认，负值或 max 小于 base 在 Load 拒绝。整数转 duration 和指数增长有饱和保护。直接构造配置的嵌入调用方也有默认回退及 max/base 保护。

所有生成的显式 HTTP 请求仍只经过 `doRequest`：先检查请求状态和总次数，再等待退避，等待结束重新检查，最后扣减预算、开启 trace、调用 Client.Do。首次实际 Do 不等待；后续 Do 按全请求已发送次数计算指数上界，具体延迟在上界的一半至上界间随机抖动。默认前几个后续窗口为 100–200ms、200–400ms、400–800ms，最终不超过 2 秒。普通重试、换目标和预算字段兼容重试都不能绕过。

退避使用 timer 和 context 取消，不用不可取消的 sleep，不持锁等待，不提前扣次数。预算已耗尽、请求已取消/过期或交付已开始时不再等待或发送。预检查和熔断跳过未发送 HTTP，不累加退避指数。状态码是否值得重试及目标顺序沿现有 failSpec，不在本阶段改写 429/Retry-After 的路由与透传规则。

兼容重试仍只窄匹配 400/422 的预算字段不兼容，仍同目标最多一次；第一条真实拒绝先完成其 attempt 记录，再竞争等待与发送许可。等候被取消不产生第二条虚假 HTTP attempt，也不能覆盖第一条真实拒绝证据。

## 失败归因与安全

累计非流式期限到达为 `non_stream_deadline`，返回 504、StopRequest、不计渠道熔断。父请求自身 deadline 到期也停止全部尝试，仍按客户端行为 `client_cancel` 归因，未交付时返回 504，不误当供应商网络超时；已交付时只停止当前流，不改写既有 HTTP 状态，同样不计渠道故障。请求预算、流式首内容期限及客户端主动取消保持各自分类；供应商响应头超时和可重试 HTTP 错误继续沿既有分类。

重放资格保护也覆盖非流式：带原生外部操作或状态续接的请求，在发送后遭遇网络、5xx/429、读体或转换失败时，不因尚未向客户端交付就自动重放。明确的预算字段拒绝仍可按窄兼容规则修正，但下一次发送照样受总预算、累计期限和退避控制。普通生成在预算内维持原有重试和选路行为。

SSE 完整事件保留、终态校验、原生扩展及兼容诊断、预提交缓存上限、交付后禁止重放继续强制执行；不引入 strict。独立 attempt 时长从实际 Do 前开始，不包含此前等待；relay 时长可包含本轮退避。没有发送的等候停止不造 HTTP attempt，旧 relay 行数仍不等于真实客户端请求数。

## 验证设计

- 非流式两目标共用一秒窗口，第二目标响应头/成功体/错误体/兼容检测体/兼容修正后的体只能用剩余时间。
- 即使收到完整 JSON，只要响应体尚未读完，也不能提前返回成功；超时不泄露暂存正文。
- 普通及兼容退避取消后不增加 Do/attempt，总预算为一时不能等出额外兼容请求。
- 截止时间在退避中到达，返回本地期限归因、不计渠道故障；兼容首个 400 attempt 保留真实状态。
- 兼容、普通重试及目标切换的预算字段、trace 序号与既有路由顺序正确，等待间隔为正。
- 抖动范围、指数封顶、整数溢出保护、首次免等待、预算耗尽/已交付不等待、commit 与期限裁决。
- 非流式原生操作失败禁止重放，已有流式交付后长期流可超过首内容期限继续完成。

# 熔断半开恢复：有限探测租约

## 需求与范围

用户要求：“做熔断半开恢复的有限探测租约，避免冷却结束后并发请求同时涌回主目标，保持手动和故障转移的现有含义、固定主备顺序，安全边界继续强制执行。”

本阶段让同一模型ID在半开期间同时最多有一个真实relay探测，跨分组共享。探测由真实用户请求触发，没有后台生成调用、新的路由策略或评分。正常闭合状态保留既有并发调用行为。

## 状态与恢复

| 状态 | 准入 | 结果 |
| --- | --- | --- |
| closed | 普通调用可并发，携带当前代次 | 健康失败按现有普通阈值、等头假死按既有快速阈值累计；达到阈值open |
| open，冷却未结束 | 拒绝，无上游Do | 继续按固定顺序选下一候选 |
| open，冷却已结束 | 实际发送前原子转half-open并占一个租约 | 竞争失败不等待、不扣次数、不造HTTP attempt |
| half-open，租约忙 | 拒绝其他探测 | failover顺延备用；manual只用指定成员，返回503 |
| half-open，租约空闲 | 下一个真实请求可取得租约 | 有效成功累计达到原有阈值后closed，默认2次 |

半开探测的健康失败立即重开并重置冷却，不在同目标再次普通重试。429、取消、客户端写失败、资源限制、预算或累计期限终止及本地错误均沿用 `failSpec` 判定，中性释放，不误算供应商故障或恢复成功。中性结果不清除已完成的有效成功；成功、中性、成功仍满足默认两次有效成功。429冷却是另一套独立状态，不由探测成功清除。

`Allow`只作路由预览，不再改变熔断状态或预占名额。真正的准入由互斥锁保护的 `Acquire` 完成，检查与占用不可分割。`probe_busy` 和 `stale_lease` 对外仍使用既有 `circuit_open` 归因及503，不冒充供应商失败。忙时 `Retry-After: 1` 仅表示建议稍后重试，不代表租约将在一秒后到期。

## 租约生命周期

实际发送顺序为：资源检查 → 请求取消/期限与剩余预算检查 → 限流检查 → 已有租约有效性检查 → 可取消退避 → 限流复查 → Acquire或复用已有租约 → reserve预算 → trace.begin → HTTP Do。

租约属于一次relay，覆盖顺序的预算字段兼容重试、完整非流式body读取和转换，以及流式事件校验和交付。第一条兼容请求body关闭后仍持有同一租约，第二次Do前复查其代次；两次Do分别扣统一预算、分别留attempt，最终只算一次恢复结果。

正常退出时先关闭body和停止watchdog，再Finish释放名额，之后才写最终AttemptWrite/LogWrite，避免最终观测写入阻塞占住已结束的探测。兼容重试中间的AttemptWrite仍位于同一未结束relay内，租约继续持有；即使记录阻塞，也不会放行重叠探测。预检查失败未取得租约，无须释放；取得后reserve因取消或预算变化失败，则由relay defer中性释放，不制造Do记录。

不使用固定TTL提前释放活跃租约：上游长流仍在进行时，即使墙钟推进很久，也不能允许第二个半开探测。非流式累计deadline、流式首内容累计deadline、交付后idle watchdog及客户端取消继续控制生命周期；持续正常输出的长流会持续占有名额。这是有意的并发保证，没有新增独立探测超时或配置。

## 迟到结果隔离

所有普通调用和探测都持有代次令牌。进入open、开始新一轮half-open、恢复closed时推进代次；Finish同时检查代次与探测持有者。迟到成功不能恢复新一轮熔断，迟到失败不能再次延长其冷却，旧令牌不能释放新探测。Finish幂等，并发或重复调用也只结算一次。

生产relay结果统一经租约Finish上报。旧 `Record` / `RecordStall` 保留用于嵌入兼容和测试故障注入：无令牌成功仅可更新closed状态，不能恢复open/half-open；显式故障可开启新代次。该旧接口不具备识别调用来源代次的能力，不能用于生产迟到结果上报。

## 路由与安全边界

- manual只解析激活成员，熔断或名额忙也不自动切成员。
- failover继续按priority、成员ID稳定主备顺序遍历；主目标恢复后，新请求继续优先使用主目标。
- 跳过和Acquire竞争失败不产生HTTP attempt、不扣Do预算；兼容重试仍使用请求级统一预算和累计deadline。
- 原生状态操作禁止重放、交付后禁止重放、SSE预提交缓存/完整事件/终态控制、资源限额、取消和兼容诊断继续强制执行，不引入strict。
- breaker仍按模型ID共享；429继续按连接指纹和配置的model/channel作用域单独冷却。后续已补完整[切换诊断](2026-10-23-routing-diagnostics.md)和可选[渠道并发上限](2026-10-23-channel-concurrency.md)。

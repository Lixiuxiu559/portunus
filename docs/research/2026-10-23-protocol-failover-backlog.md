# 协议转换与故障转移：使用边界和待完善清单

日期：2026-10-23。当前决策：停止扩展功能，先验收和使用；只有验收失败或实际调用出现问题时才进入修复。此清单用于保留边界，不是下一轮开发计划，也不表示必须全部完成才能使用。

本轮普通对话、流式输出、工具调用、主渠道失败切备用的执行证据与结果统一见[实际验收记录](2026-10-23-protocol-failover-acceptance/README.md)。本清单不预先认定验收通过；本地模拟、实际进程调用、真实供应商及真实 SDK 的结果必须分别记录。

## 已完成范围

- 请求及响应原生扩展保留、目标兼容诊断、类型化流转换、完整 SSE 与终态识别。
- 预提交缓存、交付后禁止重放、可能执行原生操作后的安全重放限制。
- 全请求 HTTP 总尝试预算、跨目标累计期限、可取消退避、整链资源限额。
- 仅手动与固定主备故障转移；429 按模型/渠道作用域冷却、半开单探测租约、完整切换诊断、可选渠道并发上限。
- strict 配置及兼容拒绝分支已移除，安全边界仍强制执行。跳过和本地准入拒绝不制造 HTTP attempt。

实施范围分别见[转换方案的后续实施记录](2026-10-23-protocol-conversion-redesign.md#13-后续实施状态)、[当前诊断模式](2026-10-23-protocol-diagnostics-only.md)、[429 冷却](2026-10-23-scoped-rate-limit-cooldown.md)、[半开探测](2026-10-23-half-open-probe-leases.md)、[切换诊断](2026-10-23-routing-diagnostics.md)及[渠道并发](2026-10-23-channel-concurrency.md)。旧研究文档中“本阶段未做”和“后续建议”描述其编写时点，不覆盖这些后续实施事实。

## 使用中优先验证和按需修复

| 优先级 | 项目与当前边界 | 何时处理 | 处理前的使用方式 |
| --- | --- | --- | --- |
| 当前验收 | 普通/流式/工具/主失败切备用的组合调用，及对应日志与尝试证据 | 本轮验收发现实际问题时修复并复验；结果和未验证部分写入验收记录 | 只把有执行证据的客户端、协议与渠道组合视为已验证；HTTP 200 不能代替正文、工具参数和终态检查 |
| 遇到即修 | 实际供应商或 SDK 的协议差异、断流、错误归因、工具配对或切换错误 | 日常客户端复现失败，或当前验收失败 | 保存脱敏最小样本及预期，补针对性回归；不借修复扩大功能范围 |
| 有明确需求后处理 | 更换连接后隔离旧熔断状态：BreakerStore 当前按模型 ID 保存，429 冷却则另按有效连接指纹隔离 | 同一模型记录更换 Key、URL 等连接配置后，旧熔断妨碍新连接 | 了解旧熔断可能延续至恢复；如改造，应隔离健康状态和迟到结果，渠道并发仍按渠道 ID 共享，不能清零在途计数 |

## 可延期的转换扩展

| 项目 | 已知边界 | 启动条件与验收方向 |
| --- | --- | --- |
| 多 choice / candidate 的完整跨协议表示 | 类型化流保留索引，但部分目标状态机继续消费首个候选；本轮没有承诺多候选完整等价转换 | 客户端实际请求并依赖多个候选时，先确定目标协议表示，再验证文本、工具、结束原因和诊断不静默丢失 |
| 缓存 usage 口径统一 | 非 Chat → 非 Chat 的部分流式路径保留历史投影，客户端缓存细项可能省略；decoder 源用量及日志仍保留 | 客户端需要这些细项或发现显示不一致时，单独明确口径和兼容变化，核对源响应、客户端输出与日志 |
| 更多跨协议能力映射及诊断覆盖 | 原生数据保留不等于目标协议能表达；当前诊断只检查指定结构层级，也不证明实际模型支持该能力 | 实际使用多模态、托管工具、引用或新增扩展时，按最小能力逐项补样本、映射和诊断；优先使用同协议渠道 |
| 可信跨请求续接 | 客户端回传的签名、密文或状态引用来源仍未验证，不能承诺任意跨渠道透明续接 | 确有有状态会话需求时，单独设计可信引用、来源绑定及生命周期；不得绕过已发送原生操作的重放保护 |

## 可延期的故障转移与运维完善

| 项目 | 当前边界 | 启动条件与验收方向 |
| --- | --- | --- |
| 删除模型后的熔断状态回收 | BreakerStore 使用进程内模型 ID 映射，目前没有显式删除回收；渠道并发仅保留活跃桶，429 冷却有界，三者不能混为同一缺口 | 长期频繁创建/删除模型或观测到状态增长时，设计不破坏在途租约和迟到隔离的回收 |
| 实时健康与容量视图 | 已有逐请求跳过、探测及容量快照；没有统一展示当前所有目标开路/半开、冷却剩余、在途数的页面 | 实际排障无法由调用日志定位时再补；快照不能宣称供应商实时在线或可用 |
| 诊断持久化与采集完整性 | RoutingTrace 已保存请求结束摘要；进程崩溃、进行中或写库失败可能没有记录，事件最多 256 条并有截断计数；这不等于完整持久化成功证明 | 需要崩溃排障、写入失败告警或准确请求统计时，设计开始/结束证据及完整性标记；不改变独立 HTTP attempt 口径，也不因写入失败重试上游 |
| 多进程及共享账户治理 | 熔断、冷却、并发计数均为进程内；不同渠道 ID 不自动共享同账户配额，重启不保留健康状态 | 真正部署多实例或同账户多渠道共享硬配额时再设计协调；单机使用无需提前引入共享存储 |
| 压力与容量基线 | 自动化回归和竞态检测不能给出长流、大响应、大量候选下的吞吐、内存和尾延迟上限 | 预计并发、数据规模明显增长或观察到性能问题时，使用隔离合成负载建立基线，再决定是否优化 |

依据：[circuit_breaker.go](../../backend/gateway/circuit_breaker.go)、[channel_concurrency.go](../../backend/gateway/channel_concurrency.go)、[routing_trace.go](../../backend/shared/routing_trace.go)及上述阶段实施记录。

## 本轮不再推进的方向

不恢复轮询，不引入权重、评分、自适应负载均衡，不恢复 strict 配置，不以提高切换成功率为由放宽预算、期限、取消、资源限制及交付/原生操作重放保护。无需为完成本清单增加新的功能阶段；正常使用，依据实际问题决定后续工作。

# Portunus 渠道余额与额度查询整体方案

日期：2026-10-21。版本：1.0。状态：建议实施基线，仅设计，未新增业务实现。

本文替代旧版 `portunus-balance-module-design.md`。依据为当前 Portunus 工作区和 [CC Switch 调查](./2026-10-21-cc-switch-balance-query.md)，不把历史设计稿当作当前能力。

> 2026-10-21 范围调整：A/B 已实施，验证见 [A/B 实施记录](./2026-10-21-quota-ab-implementation.md)。用户取消 C（Sub2API Key 限额及套餐额度），D 经用户澄清调整为参考 CC Switch 的自定义查询，采用结构化请求与字段映射；详见[自定义设计](./2026-10-21-quota-custom-design.md)。下文涉及 C 的内容保留为历史设计，不作为后续实施任务。

## 1. 目标和关键决策

为上游渠道提供可选的账户余额、API Key 限额和套餐额度查询。用户能区分“还剩多少钱”“这个 Key 还能用多少”“套餐窗口何时重置”，并看到数据来源、查询时间与失败原因。

核心决策：

1. 新建统一的 `backend/quota` 模块，余额、Key 限额、套餐窗口共用查询生命周期和展示模型。
2. 厂商预设、推理协议、额度查询适配器独立。复用已有厂商 ID 提供建议，不根据 URL 子串猜厂商，也不向 `Channel.Type` 增加余额类型。
3. 一个渠道可以有多个查询来源，例如账户余额和套餐额度；每个来源单独配置、执行、缓存。
4. 查询凭据独立建模，可显式继承渠道 Key，也可使用独立查询 Token、用户 ID 等。
5. 结果只用于展示与提示，不改分组策略、不触发生成熔断、不以零余额阻止调用。
6. 第一版用原生适配器和结构化 NewAPI/Sub2API 配置，不引入 JavaScript 引擎、用户脚本或规则 DSL。

余额读取属于上游资源观测，不恢复模型价格、调用费用计算、成本路由或账户结算。Portunus 仍是本地运行的桌面聚合网关，管理接口继续限定本机。

## 2. 当前基础与依据

| 已确认事实 | 依据 |
|---|---|
| 渠道已有 ProviderID、ProfileID、AdapterID，Type 仍是推理协议 | `backend/channel/channel.go` |
| `upstream` 已集中厂商预设及生成/模型发现连接解析 | `backend/upstream/connection.go`、`presets.go` |
| 管理 API 可以独立扩展，不必把观测塞进生成请求 | `backend/api/channel_connection.go` |
| 渠道删除由 API 层事务编排多模块清理 | `backend/api/channel.go` |
| 当前 cron 模型同步是同步执行的，慢上游会延长这一轮 tick | `backend/cron/cron.go` |
| 当前客户端列表刷新和模型同步是两个操作 | `web/src/renderer/pages/Channels/index.jsx` |
| 产品已退出本地价格配置与费用计算 | `docs/product/PRODUCT.md` |
| CC Switch 的原生余额、套餐、订阅、脚本分别查询，再适配展示 | 前述调查及其源码证据 |

旧稿的“凭据就是 Channel.Key”“依赖域名识别”“Total=0 表示未知或无限”“余额辅助 failover”不再采用。旧稿把 Portunus 描述成没有桌面形态，也与当前产品状态不符。

置信度：上述代码与职责判断高。具体厂商端点、权限和套餐字段仍须在接入批次查阅官方资料并验证，本设计不宣称真实账号已通过。

## 3. 模块边界和依赖方向

```text
渠道页面：查询来源配置 / 余额摘要 / 套餐窗口 / 手动刷新
                           ↓
管理 API：参数、权限、批量查询、跨模块事务
                           ↓
quota.Service：配置解析、单来源互斥、查询执行、状态更新
        ├─ 适配器注册表：描述字段、构造请求、解析响应
        ├─ 共用 HTTP 执行器：超时、状态分类、限流、响应上限
        ├─ repository：来源配置与最新状态
        └─ scheduler：后台到期查询、退避、全局并发控制
```

`quota` 不依赖 `gateway`、`router`、`protocol` 或 `upstream` 的运行时实现。生成请求与余额查询的地址、鉴权和超时策略不同，不复用 `ChatHeaders`、`NewUpstream`，也不复用生成重试循环。

`main` 注入数据库、额度专用 HTTP client，以及一个最小的渠道凭据读取函数。该函数可在调用方提供的短事务中读取渠道是否存在及当前 Key，不把整个 Channel 模型传入厂商解析器。适配器不读数据库、不直接执行网络请求。

渠道预设页可通过显式元数据关联推荐的查询适配器；推荐表由额度模块维护，通过 API 返回。`upstream` 不反向导入 `quota`，前端不硬编码厂商支持表。

建议文件结构：

```text
backend/quota/
  types.go                结果、状态、错误和配置 DTO
  source.go               来源配置校验与凭据解析
  registry.go             唯一适配器注册表及描述信息
  execute.go              共用 HTTP 执行与错误分类
  service.go              手动/定时查询共用入口
  repository.go           两张表的读写与事务接口
  scheduler.go            一个调度器、一个有界队列
  adapter_deepseek.go      原生请求与响应映射
  adapter_siliconflow.go
  adapter_openrouter.go
  adapter_newapi.go        结构化模板，不执行用户代码
  adapter_sub2api.go
```

初期适配器与核心使用同一个 Go package，避免 `quota → providers → quota` 循环。文件按职责拆，暂不新增多层工厂、插件系统或依赖注入框架。只有真实出现多实现替换需要时再抽 repository 接口，测试可直接使用临时 SQLite。

## 4. 渠道与查询来源

### 4.1 一个渠道对应多个来源

新增 `channel_quota_sources`，不向 Channel 继续堆查询专用字段：

| 字段 | 含义 |
|---|---|
| `id`、`channel_id` | 来源身份及归属渠道 |
| `name` | 用户可读名称，例如“账户余额”“Coding 套餐” |
| `adapter_id` | 稳定标识，例如 `deepseek.balance`、`newapi.account` |
| `schema_version` | 该配置结构版本 |
| `config_revision` | 每次有效配置变化递增，防止旧查询覆盖新配置 |
| `enabled` | 是否允许查询；新增默认关闭 |
| `query_base_url` | 已展开保存的查询根地址，可与推理根地址不同 |
| `credential_mode` | `inherit_channel_key` 或 `dedicated` |
| `credentials` | 专用秘密字段，写入与读取 DTO 分离 |
| `options` | 按适配器校验的结构化参数，例如 user_id、额度换算 |
| `auto_refresh_minutes` | 0 关闭定时，非零首期允许 1–60 分钟，建议 5 分钟 |
| `created_at`、`updated_at` | 维护时间 |

Channel 不导入 quota。删除渠道时由管理 API 在现有同一事务中调用 `quota.DeleteByChannelTx`，清理来源与状态。来源删除也同步清理其状态。

一个来源绑定一种明确查询含义。需要同时看账户余额和 Key 限额时添加两个来源，不能在运行时根据响应或账户类型无提示地切换查询含义。

### 4.2 继承与专用凭据

- 继承模式只在执行时读取当前渠道 Key，不复制成第二份秘密；保存界面明确显示继承关系及目标主机。
- 专用模式允许保存 API Key、账号 Access Token、用户 ID 等。后续签名类凭据再增加类型化字段，不把 AK/SK 伪装成一个字符串 Key。
- 读取接口只返回 `has_token` 等存在标记，表单不回显秘密。更新时字段缺失保留、显式 `clear` 清除，空白输入不自动删除旧秘密。
- “使用已有凭据”和“测试草稿”均由后端解析，前端不需要读取明文。
- 首期沿用当前本地凭据存储信任边界，明确新增秘密同样存于本机数据库；不声称已提供字段级加密。秘密存储集中封装，后续可替换 Keychain 等实现，不让适配器知道存储位置。

查询根地址是独立快照，不随推理 Base URL 变化而静默改写。只更新渠道 Key 时，继承凭据的来源必须立即使旧状态失效；专用凭据来源不受无关 Key 变动影响。

### 4.3 来源重复与共享账号

允许同一渠道有多个不同查询含义；同渠道相同适配器和相同查询目标在 UI 提示可能重复。首期不自动识别跨渠道共享账户，不按 Key 去重，也不把多个来源金额相加为全局余额：同一账户可能重复出现，不同币种也不能直接合计。

## 5. 适配器契约

唯一注册表由稳定 adapter_id 映射到实现及 Descriptor。Descriptor 提供名称、结果类别、支持的凭据模式、配置字段、可建议的厂商 ID、地址策略及资料链接。UI 和执行器从同一注册表读取，不分别维护支持列表。

接口职责限定为：

```text
Describe()                          返回配置与能力描述
Validate(SourceConfig)              校验本适配器字段
BuildRequest(ResolvedSource)         生成 URL、方法、Header、可选 Body
Parse(ResponseMetadata, body)        解析为统一 Snapshot 或类型化失败
```

执行器统一发送请求与读取响应。解析器只对响应字段和业务状态负责；不得自行发第二次请求、读 Key、写数据库或睡眠重试。如果未来适配器必须调用多个接口，显式扩展查询步骤契约并共享总预算，不在 `Parse` 里藏网络请求。

原生适配器第一批使用核对过的官方 HTTPS 目标，严格按 host 校验；私有部署 NewAPI/Sub2API 的目标由用户配置，保留部署路径前缀。不要对任意 URL 字符串使用 contains 判断厂商。

## 6. 统一结果模型

### 6.1 Snapshot 与 Item

每次成功查询返回一个 Snapshot，内含多个稳定 ID 的 Item：

| Item 字段 | 语义 |
|---|---|
| `id`、`label` | 钱包或窗口标识与展示名 |
| `kind` | `balance` / `spending_limit` / `usage_window` |
| `scope` | `account` / `api_key` / `plan` |
| `unit` | 类型 money/count/tokens/percent，加代码 USD/CNY/requests/tokens/% |
| `remaining`、`used`、`total` | 可缺失的十进制字符串；空值与数值 0 分开 |
| `used_percent` | 可选数值，来自上游或可靠分子/分母，不由界面猜测 |
| `limit_state` | `unknown` / `limited` / `unlimited` |
| `resets_at` | 可选窗口重置时间，不提供就显示未知 |
| `source_updated_at` | 上游有提供时记录其数据时间，与本地查询时间分开 |
| `account_status` | 仅在上游明确提供时记录 active/expired/suspended/unknown |

金额和数量使用受限、校验后的十进制字符串，避免二进制浮点显示偏差；JSON 响应中的数值和数字字符串统一由后端解析。百分比使用可选数值，拒绝 NaN/Infinity。实现时集中数值解析与换算，不让每个厂商和页面各写一套。

保留上游明确提供的负余额和超过 100% 的使用比例，不篡改原数值；进度条视觉长度可以限制在 0–100%，文字仍显示真实值。

### 6.2 必须明确的语义

- 未知用 null/缺失表示，不用 0 或 -1 代替。
- 无限用 `limit_state=unlimited` 表示，不把 -1 展示为负余额。
- 总量未知时不画进度条；total=0 也不表示无限。
- 只有 used_percent 的窗口，不伪造绝对 total/remaining。
- 余额为 0 不表示 Key 失效；查询 403 也不表示生成权限失效。
- 金额与次数、token、百分比不混算；查询结果不产生 currency 转换。
- 首期返回完整来源结果或明确失败，不把缺失的必需窗口当作 0。允许未知的可选字段保留空值。

例如一个余额来源可以返回 USD/CNY 两个钱包，一个套餐来源可以返回 5 小时和周窗口。展示层按 Item 语义统一渲染，不需要按厂商名称分支。

## 7. NewAPI 与 Sub2API 适配

### NewAPI 账户余额

按调查中的模板作为候选实现：站点根地址下 `/api/user/self`，账号 Access Token 与用户 ID 分别构成 Authorization 和 New-Api-User。推理 Key 不自动当作账号 Token。

`quota/used_quota` 首先按原始额度单位表达。可显式配置正数 `quota_per_unit` 与展示单位进行换算；500000 只能作为待确认的建议值，不作为所有站点通用真相，更不能默认标美元。预览同时展示原始值和换算设置，未配置换算时显示“额度单位”。

不同部署的用户接口、权限、换算和代理前缀可能不同；遇到不兼容时给出明确错误，不盲目尝试多个管理端点。OneAPI 若经验证兼容可作为同适配器的配置档，不提前宣称兼容。

### Sub2API Key 用量

使用 API Key 认证的 `/v1/usage` 作为候选实现。根据当前部署核对它返回的账户、Key 或套餐范围，正确映射 limit/used/remaining/unit；不限量映射为 unlimited。查询 Base URL 的版本后缀由适配器明确定义，不依靠全局删除 `/v1`。

两者都采用结构化字段，不提供自由 Header/表达式编辑器；确需特殊部署时增加有测试的配置档。

## 8. 状态、错误和缓存

### 8.1 两张表，共用一套查询状态

新增 `channel_quota_states`，每个 source_id 只有一条最新状态，首期不存每次历史、不存原始响应正文：

```text
source_id / config_revision
last_attempt_at / last_completed_at / last_outcome
last_success_at / snapshot_schema_version / snapshot_json
snapshot_usable
failure_code / failure_category / safe_message / upstream_status
next_allowed_at / next_scheduled_at / consecutive_failures
```

`last_success_at` 与 `last_attempt_at` 永远分开。失败更新最近尝试、失败状态及按类别裁决的快照可用标记，不把上次成功时间刷成现在。是否展示旧值由以下明确规则决定，不能靠前端是否缓存着对象决定。

`snapshot_usable` 是独立持久化标记，默认 false。相同配置版本查询成功才置 true；认证/权限/配置失败或查询身份变化置 false。后续临时错误、取消或刷新开始都不能把它重新置 true。这样“先鉴权失败、再遇到断网”也不会复活之前身份的余额；详情保留的旧值须明确标为失效记录。

### 8.2 类型化错误

| 情况 | 分类 | 行为 |
|---|---|---|
| 连接、超时、读体失败，HTTP 5xx | temporary | 可保留限时旧值，安排退避 |
| HTTP 429 | rate_limited | 遵守合法 Retry-After，限制下一次自动与手动请求 |
| HTTP 401/403 | authentication/permission | 立即展示凭据或查询权限问题，隐藏主摘要旧值；停止自动重试直到配置变化或用户手动刷新 |
| 未支持适配器/缺少字段/非法地址 | configuration | 执行前拒绝，不发请求 |
| 非 JSON、缺少必需字段、业务错误 | invalid_response/business | 展示具体安全错误；不靠无限重试掩盖。自动刷新暂停，修改配置或手动重试恢复 |
| 用户取消/应用退出 | cancelled | 不判上游故障，不增加失败退避计数 |

错误携带稳定 code、category、retryable、upstream_status、next_allowed_at 和安全文案。前端不匹配错误字符串，不以本地 API 的 401 冒充上游 401。

### 8.3 新鲜与陈旧状态

- 自动刷新来源的新鲜期限为配置间隔；仅手动刷新来源默认 5 分钟。
- 正常成功记录的新鲜度与可展示性分离：闲置成功值保留并明确原查询时间，不把本地缓存老化称为账户过期。
- 查询失败后的旧值最长展示年龄为 `max(10 分钟, 2 × 新鲜期限)`，锚定真实 last_success_at。
- 最近一次临时失败，即使旧值尚在期限内，也显示“上次查询成功值，最新刷新失败”。新鲜期限过去显示 stale。
- 查询失败且超过保留年龄，不再把旧数值放在主摘要，显示“更新失败”；详情保留历史查询记录及时间。取消不按上游失败处理。
- 认证、配置或查询身份变化立即使旧值不可作为当前结果，不等待 TTL。
- 应用重启后由时间和配置版本重新判断缓存，不能把数据库里旧 success 当作刚查成功。
- 禁用来源不删除配置，停止调度，主列表显示“查询已关闭”；重新启用后重新获取。

网络状态与数据新鲜度是两条维度，不能把“有缓存值”简化成 success=true。

## 9. 查询执行、并发和调度

手动刷新、定时刷新和测试草稿共用执行器。网络请求在数据库事务外完成；事务仅用于读取版本和原子提交状态。

执行流程：短读事务一致地读取来源版本及当前凭据 → 校验与取得并发槽 → 构建请求 → HTTP/解析 → 校验结果 → 提交前事务核对来源版本及渠道存在性 → 写入状态 → 返回视图。

### 单来源互斥与旧结果隔离

- 同一来源最多一个实际请求，前端重复点击不叠加；已有请求时返回 202 in_progress，调用方读状态，不再发送一份。
- 全局默认并发 2，队列有界，来源重复入队忽略。手动请求没有空槽时快速返回限流提示，不占满管理 HTTP 请求。
- 来源删除、禁用、配置变化时取消可取消的旧任务；即便取消未及时生效，旧结果也不能提交。
- 渠道 Key 真正变化时，管理 API 在更新渠道的同一事务中调用 `quota.InvalidateInheritedSourcesTx`：递增所有继承来源的 config_revision，并使快照不可用。专用凭据来源和只改渠道名称的操作不受影响。
- 所有受支持的渠道 Key 写入路径必须复用这一管理编排；未来增加导入/恢复入口时也要覆盖。不能在 channel 包反向引用 quota，也不通过全局事件或包级回调维持正确性。
- 初次读取的来源版本和继承 Key 必须来自同一短读事务，避免新版本配到旧 Key。提交时在写事务内核对渠道存在、enabled 及 config_revision；不符则丢弃结果。来源和状态在同一主库，版本变更与状态写入由事务串行裁决。
- 批量摘要同样比较状态与来源版本，只展示匹配且 snapshot_usable 的快照。因此持久化 config_revision 已覆盖 Key 依赖，无需另存秘密摘要或再建一套渠道凭据版本字段。
- 手动任务绑定请求 context，取消后停止其请求；后台任务绑定服务生命周期。互斥不共享一个会被任意调用方取消的 context，也不实现多调用方等待同一响应的复杂引用计数。

### 调度与网络边界

额度模块只有一个生命周期受控调度器和一组有界 worker，由 main 启动和关闭。不要每个渠道启动 ticker，也不要塞入现有同步模型的串行 tick：慢模型发现不应阻塞余额刷新。

自动刷新默认关闭。启用后按来源时间到期调度、增加小抖动；临时失败按 1/2/5/10 分钟退避，最长 30 分钟；429 的 Retry-After 优先，异常值有边界校验。一次查询不自动重发 HTTP 请求，自动调度重试才产生下一次查询。

默认单次 HTTP 超时 15 秒、查询总期限 20 秒、响应上限 1 MiB，禁止 HTTP 重定向，超限按安全错误返回。额度专用 client 共用连接池，不和生成请求的长流式超时混用。

只允许适配器定义的读取操作。私有站点由用户显式配置，地址策略允许必要的本机 HTTP 场景；原生官方适配器不静默向任意目标发送凭据。日志不记录 Key、Token、认证头、带凭据 URL 或原始正文，不向生成日志表写查询记录。

## 10. 管理 API 与返回约定

全部沿用 `/api` 本机管理访问边界，不增加 `/v1` 对外余额接口。

| 接口 | 职责 |
|---|---|
| `GET /quota/adapters` | 适配器目录、推荐厂商、配置描述 |
| `GET /channels/:id/quota-sources` | 该渠道来源与脱敏配置/状态 |
| `POST /channels/:id/quota-sources` | 新增查询来源，默认不查询 |
| `PUT /quota-sources/:id` | 更新配置，要求预期 revision，冲突返回 409 |
| `DELETE /quota-sources/:id` | 删除来源和状态，不删除渠道 |
| `POST /quota-sources/preview` | 使用 channel_id、可选 source_id 和草稿执行只读查询，不保存配置/状态、不启用定时 |
| `POST /quota-sources/:id/refresh` | 按已保存配置刷新并保存最新状态 |
| `GET /quota/summaries?channel_ids=...` | 批量读取渠道摘要，最多 100 个渠道 ID，不请求上游 |

草稿带 source_id 时必须验证它属于 channel_id，不能借用另一来源秘密。预览缺失的秘密字段由后端继承，普通 source GET 绝不返回它们。

配置非法为 400、对象不存在为 404、版本冲突为 409、本机并发或冷却限制为 429。已执行的上游查询无论成功或失败，200 返回统一状态视图，失败的上游 HTTP 状态放在结构化 failure 中，避免客户端错误拦截器误认为后台登录失效或自动重发。已有任务返回 202，带当前状态及建议轮询时间。

读取接口纯读缓存；刷新是明确 POST 操作。前端关闭请求层通用重试，由额度服务统一决定下一次查询时机。

enabled=false 的已存来源不接受普通刷新，返回明确 disabled 配置错误；用户主动的草稿预览仍可测试未启用配置。“保存并查询”明确把来源设为 enabled=true 后发一次刷新，不自动打开定时。

## 11. 前端交互

### 渠道卡片

未配置时显示轻量入口“配置余额/额度查询”，不因选择了厂商就自动发网络请求。配置后按来源展示账户余额、Key 限额或套餐窗口，显示单位、上次成功时间及 stale/error 提示。

一个渠道多个来源可折叠，稳定按用户配置排序；不把多币种或共享账号金额合计。余额不足、套餐用尽和查询失败使用不同状态文案，不能都叫“渠道不可用”。

列表先获取渠道，再批量获取摘要，避免每张卡片分别请求。页面刷新摘要只读缓存；后台刷新与“立即查询”分开。页面可见时轻量轮询在途状态，隐藏后暂停前端轮询，自动查询由后端调度统一负责。

查询配置或渠道 Key 保存成功后，前端立即使受影响摘要缓存失效并重新读取，不等待下一轮定时；后端版本校验仍是正确性依据，前端通知只用于及时更新画面。

### 来源配置面板

编辑现有渠道时使用单独的“余额/额度查询”面板，不继续扩张当前“新增渠道”表单。

流程：选择查询含义/适配器 → 查看目标主机 → 选择继承或专用凭据 → 填必要参数 → 可选测试草稿 → 保存并明确选择是否启用/定时查询。

“测试查询”返回实际读取结果，不发送模型生成请求。草稿变更使结果失效，取消/关闭面板终止请求，旧异步响应不能覆盖新草稿。保存本身不隐式立即查询；如需首次读取，提供明确的“保存并查询”动作。

复用展示组件 `QuotaSummary`、`QuotaItems`、`QuotaSourceEditor`。数据获取与草稿逻辑独立 hook，页面不写厂商字段解析或金额运算。

|---|---|---|
| A：核心与契约 | 两张表、结果/错误模型、注册表、共用执行器、版本隔离、状态 API、共用展示 | 用测试适配器完成配置→查询→状态→界面闭环；测试适配器不进入生产目录 |

自由脚本、任意表达式、余额历史曲线、全局余额汇总、充值、自动切换渠道与成本策略均不进入以上必交范围。

## 13. 测试设计与质量门

复用 Go testing/httptest/临时 SQLite、现有前端 node:test 与浏览器验收，不新增测试框架。

| 场景 | 关键预期 |
|---|---|
| remaining=0 / 未知 / 无限 / 负余额 | 四种含义不混淆，类型与单位正确 |
| 两币种、一个来源多窗口、两个渠道共账号 | 分开展示，不合并金额；稳定 Item ID |
| 只返回 used_percent、total=0、超过100% | 不伪造绝对额度，不除零，不截断文字数据 |
| NewAPI 换算未填/500000/其他正数/非法值 | 原始单位可用，显式换算正确，无默认 USD 假设 |
| 专用 Token、继承 Key、缺失/空/clear | 凭据不串用，不回传，不误清除 |
| HTTP401/403/429/5xx、读体失败、非法JSON | 类型化分类，冷却与旧值展示符合约定 |
| 断网超过有效期、重启、先鉴权失败再网络失败 | 不无限展示旧余额，不复活失效身份快照 |
| 多次点击、调度与手动并发、不同来源并发 | 同来源一次实际请求，全局有界，互不串状态 |
| 查询中改配置/Key/删除渠道/禁用来源 | 旧结果不能写回或展示，数据库无孤儿记录 |
| 草稿借用其他来源ID、关闭面板、迟到响应 | 归属校验，取消生效，不保存或污染新草稿 |
| 重定向、超大响应、超时 | 请求受限，不输出秘密、不写生成日志 |
| 不同协议的同厂商渠道 | 查询能力独立于生成协议，现有路由与转换无行为变化 |

每阶段完成后运行受影响测试；集成时 Go 全量测试/vet/build 与前端测试/构建。对跨模块事务、并发结果提交、秘密处理和缓存状态进行独立 diff-review。若有现成复杂度工具再作量化审计，不为追指标安装工具或无意义拆函数。

## 14. 防止代码堆积的实施约束

1. 新增厂商只增加适配器文件、注册项和解析 fixture；如果还需改渠道页面、网关和调度器，先检查抽象边界是否失效。
2. 所有网络调用只经过 execute，所有结果归一化只在后端，所有错误状态只用类型化分类。
3. 生命周期、去重、缓存和调度共用一套服务；不按余额/套餐各写一条流水线。
4. 配置持久化与执行凭据分离，适配器不接触 Channel 或数据库。
5. 领域值的未知/无限、版本、失败与陈旧时间是显式字段，不能靠魔法数字、字符串匹配或 UI 状态猜测。
6. 不用“以后可能需要”引入通用脚本引擎、跨渠道账号中心或插件框架。扩展点以已明确的查询差异为边界。

## 15. 未确认项与交付边界

- 新增来源和结果 schema、接口与批次是本方案的设计决策，尚未写入生产代码或产品“已交付”状态。

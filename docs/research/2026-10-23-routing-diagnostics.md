# 固定主备切换诊断

## 范围

本阶段补充用户要求的完整切换诊断：候选跳过原因、半开探测名额、备用选择和最终停止原因。路由仍仅manual/failover，候选仍按priority、成员ID固定排序；诊断只观察现有执行，不参与候选评分、重试或安全判断。

独立 `shared.RoutingTrace` 每个进入relay handler的请求保存一行，使用现有 `X-Request-Id` 关联。`Log`、用量统计、请求关联列表和 `UpstreamAttempt` 的口径不变；未发送的跳过和准入失败不制造HTTP attempt。鉴权在handler之前，鉴权失败不产生本诊断。

## 采集内容

| 事件 | 含义 |
| --- | --- |
| candidate_skipped | 候选因作用域冷却、熔断开路或半开名额忙而跳过；保留静态原因、冷却作用域及重试秒数 |
| candidate_selected | 准备执行某一候选；primary/backup取固定候选序号，retry表示同候选重试，选中不证明已发送 |
| admission_blocked | 到实际Do前被资源、控制、限流或租约检查阻止；包含退避后新增冷却或Acquire竞争失败 |
| probe_acquired | 实际取得半开探测名额；顺序兼容Do不重复取得 |
| probe_finished | 探测结束，区分成功、健康失败、等头假死、中性释放及旧代结果未应用 |
| http_attempt | 紧邻真实HTTP Do记录；兼容重试仍分别占用统一预算，沿用initial/retry/failover/budget_compat原因 |
| relay_finished | 完整目标调用结束，读取真实success及failReason，不从HTTP200或返回err=nil推断成功 |
| target_exhausted | 当前目标因不可重试、重试用尽、等头假死或新熔断状态结束 |

候选编号从1开始，反映固定主备位置；主目标被跳过后备用可能是首个Do，此时新诊断标为backup，旧attempt的首条initial/sequence=1保持原义。事件只存ID、固定枚举、布尔与数值，不存请求/响应正文、URL、凭据、原生签名、供应商错误原文或动态字段名。

探测Finish在原有锁内返回结果是否应用，新诊断不会将失效代次的迟到成功写为当前探测恢复成功；没有改变状态转移条件。最终AttemptWrite/LogWrite及本诊断写入均发生在探测名额释放之后；兼容中间AttemptWrite仍属于未结束relay，保持租约。

## 最终摘要与边界

摘要单独保存结束结果、停止原因、底层错误分类、网关HTTP状态、实际显式Do计数和最后选中候选。停止原因包括处理成功、交付后失败、原生操作禁止重放、客户端取消、资源限额、尝试预算、累计期限、无可用候选或候选用尽，以及转换/流式校验安全停止、装配前请求拒绝。已交付流失败即使为兼容返回nil，也记为committed_failure；不再换目标。非流式客户端Write报错只补诊断，不改变原有重试、响应或调用日志。

`delivery_started`表示开始尝试交付模型响应，不包含前置拒绝的错误信封，不证明客户端收到完整响应。`relay_succeeded`仅表示网关观察到调用处理成功，不是客户端接收凭证。最终状态不加入旧请求列表的成功率或数量统计。

每请求最多保留256条事件，多余事件记入 `dropped_events`；最终摘要和最后选中候选不受事件截断影响。这里的“完整”指覆盖关键决策位置，不承诺进程崩溃、尚在进行、未注入writer或写库失败时也有记录。缺少诊断不推断没有跳过或没有HTTP调用。

依赖 `Deps.RoutingWrite` 可选注入；生产显式使用独立日志库，测试与嵌入调用可nil。同步写入失败仅输出固定请求ID提示，不输出可能含SQL参数的驱动错误，不触发上游重试。持久化表随日志库迁移，过期时按started_at分批清理，不改变旧deleted计数。

资源限制、请求总预算、累计期限、取消、429作用域冷却、半开单名额、原生操作及交付后禁止重放继续由原判定强制执行，不引入strict或并发上限。

## 查询与展示

`GET /api/logs/routing?request_id=...` 精确返回 `{data: trace}`；空白请求ID返回400，无记录返回 `{data:null}`，不从旧日志猜测或回填。接口沿用管理API的本机访问约束。

日志详情新增“网关切换诊断”，显示固定候选序号、渠道及模型ID、作用域/剩余重试时间、探测取得和结束、备用选择及最终摘要。未采集、加载失败、事件截断分别提示；未知枚举保留原值。查询支持刷新，切换请求/关闭详情后忽略旧响应与旧错误，原HTTP尝试详情继续独立展示。

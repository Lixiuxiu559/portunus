# 前端规范与性能检查（2026-10-26）

基线：`d2392d5`。范围为六个页面入口、公共布局/表格、渠道表单和模型选择、分组拖拽、接入配置、请求与缓存、CI 和类型检查。采用独立规范审查、性能代码调查、主任务浏览器实测，再独立复查实现 diff。不是对每个历史文件的穷尽证明。

## 规范检查

仓库明确规则来自 `CLAUDE.md`、`ARCHITECTURE.md`、`docs/product/DEVELOPMENT.md` 和 CI；没有独立的 React/格式化编码规范或 ESLint 配置。未发现违反正式/Dev 隔离、管理访问边界、配置写入或统计口径的硬性规范问题。以下区分工程检查缺口与维护建议，不将个人风格偏好定性为违规。

| 项目 | 证据与影响 | 本轮处理 |
| --- | --- | --- |
| 类型检查失效 | TypeScript 7 执行 `tsc --noEmit` 时，`baseUrl` 报 TS5102；临时移除后，TSX 导入 JSX 又报 TS7016 | 移除废弃配置，允许加载 JS，增加 `typecheck` 脚本并加入 CI |
| 所有页面静态加载 | `App.jsx` 连带加载拖拽库、日志详情及低频编辑器，首包约 1.03MB | 页面和低频编辑区按需加载；启动前只预加载地址对应的一页，避免首次 Suspense 额外等待 |
| 候选选择开销无界 | `ModelPicker` 挂载全部候选，逐行 `selected.includes`，全选后为平方级成员查询 | `useMemo` 派生结果、Set 查找、每页最多 50 项；全选仍针对完整候选，搜索覆盖全部页 |
| 搜索草稿影响拖拽列表 | `Groups` 持有输入草稿，每次按键重建全部分组/成员 JSX | `GroupSearch` 持有草稿，仅提交或清空已生效查询时更新父页面 |
| 图标选择器维护两套布局 | 唯一调用方始终使用 compact，另一套 UI 没有调用 | 删除未使用分支，保留现有图片选择弹层 |

类型检查边界：`allowJs: true / checkJs: false` 使 TS/TSX 与 JS 模块互操作可以检查；**没有将全部业务 JSX 迁移为严格类型检查**。没有安装新的 lint、复杂度或突变测试依赖。

## 实测结果与边界

生产构建通过支持持久连接的回环 Node 静态服务测试，仅代理 Dev 管理 GET；未复制正式数据、执行上游生成、同步模型或写入客户端配置。首屏是相同 Dev 渠道页。每版本做 5 次独立文档导航，禁用 HTTP 缓存，配置 4 倍 CPU 节流；浏览器编译缓存未清除。就绪时间从 navigation start 计到页面 `data-page-ready=true`，不是用户感知 INP，也不代表所有机器的启动时间。

首屏实际请求 JS（资源 encodedBodySize 求和）由 **1,030,110 字节降至 605,340 字节，减少约 41%**；不是仅比较入口 chunk。初始渠道页不加载 Models、Groups、Logs、Clients、Settings 或渠道创建/编辑/额度编辑 chunk。五次页面就绪中位数为 151.9ms → 145.0ms，首次样本为 233.5ms → 259.8ms；收益主要体现在减少加载/解析体积，不能宣称冷启动总是更快。首屏耗时具有调度和本地服务噪声，原始采样随报告保存，不据此承诺固定速度。

合成组件验收使用独立生产打包的旧/新组件，同一测试页面和候选数据；测试代码已从应用源码中清理：

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 5000 个待导入候选，实际挂载 checkbox | 5000 | 50 |
| 同场景全选到确认状态的单次操作墙钟时间 | 约 5275ms | 约 113ms |
| 100 个分组、800 个成员，9 次逐字输入的脚本 CPU 时间中位数 | 152.48ms | 1.15ms |
| 同输入场景，主线程任务 CPU 时间中位数 | 176.17ms | 12.05ms |

全选时间包含浏览器工具派发/等待，且每版本仅一次样本，不作为纯 React commit 耗时或稳定倍数承诺。分组数据来自 CDP `Performance.getMetrics` 的 ScriptDuration/TaskDuration 差值，两版在同一轮、相同环境测量；不等同于端到端输入延迟。原始帧延迟采样噪声较大，未用作收益结论。

## 正确性、规范、需求三轴复查

- **Correctness**：独立审查发现 1 项中风险问题——仅有 Suspense 无法捕获后续资源加载失败，可能卸载整个应用。已增加 `AsyncContent` 局部错误边界；复查未发现新增可构造问题。真实阻断日志页 chunk 后保留六个导航，解除阻断并重新加载可恢复；阻断渠道编辑器 chunk 后保留两张渠道卡和导航，恢复后可打开编辑器。
- **Standards**：独立检查未发现本轮 diff 的硬性规范违规或明显无用途抽象；类型覆盖限制如上。
- **Spec**：按用户“深度的前端规范排查”“优化前端性能”要求核对。现有查询、跨页选择和全选范围保留；本轮没有调整权限、后端接口、持久配置或正式安装版。

## 留待后续的维护项

1. `dialog-style.css` 没有导入，多个使用处仍保留其 class 名。属于样式归属不清的维护风险；不直接全局导入，避免覆盖现有布局。
2. Channels、Models、Groups 的请求加载/错误生命周期存在重复实现。没有为此建立覆盖全仓的通用数据 hook；后续可围绕可复现竞态逐步收敛。
3. 持续背景动画与大面积 backdrop blur 有潜在 GPU 开销，但本轮没有 GPU/低端设备证据，不以猜测移除现有视觉设计。
4. 已保存模型 chip、完整分组初次挂载仍与数据规模相关；本轮只解决已测输入渲染与待导入候选开销，没有宣称所有大列表都已虚拟化。
5. 无已有复杂度、覆盖率或突变工具配置，本轮不计算 CRAP、不做突变审计；195 项单元测试不能代替全部组件交互覆盖。

本轮没有更新正式安装版或推送远端。后续安装需另按正式版备份与校验流程执行。

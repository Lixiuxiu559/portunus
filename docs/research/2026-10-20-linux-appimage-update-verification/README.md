# Linux AppImage 自动更新实机验证

日期：2026-10-20（Asia/Shanghai）。本记录及附件为未跟踪文件，未提交或发布。

## 结论

在用户授权的 `192.168.10.25`（Ubuntu 20.04.6 LTS、x86_64、内核 5.15、glibc 2.31）完成真实 AppImage 升级：`99.0.0-test.1 → 99.0.0-test.2`。后台自动下载、下载完成的全局提示、设置页状态恢复、点击「重启以更新」、AppImage 文件替换和新版自动启动均通过。

置信度：高，限于本机 Linux AppImage 路径。依据为真实更新器日志、窗口截图、运行中应用包版本、文件哈希和后端健康检查；没有使用模拟下载结果或模拟安装调用。

## 方法与隔离

- 用户明确授权将约 23 MB 的当前主进程代码、已构建渲染资源与 Linux 后端测试副本传到目标机器；未传输凭证、工作区用户数据或其他项目。
- 远程工作目录：`/tmp/portunus-update-verification-20261020`。
- 使用 Electron `42.3.3`、electron-builder `26.15.3`、electron-updater `6.8.9` 构建两个真实 AppImage，使用 `--publish never`，未上传正式更新源。
- 测试副本修改包名、appId、productName、测试版本号和输出目录；配置与缓存保存在该目录下的 `user-config`、`user-cache`。后端端口改为 `13061`。
- COS 更新地址仅在测试副本替换为 `http://127.0.0.1:18765/`，由支持 Range 的本机 HTTP 测试源提供新版清单与安装包。更新服务、事件、下载、安装和前端提示逻辑未替换。
- 新版测试副本添加环境变量控制的 CDP 端口用于观测。正式仓库的业务代码、更新地址和版本号未因本次实测修改。

## 测试工具问题与未覆盖范围

首次启动时，测试 HTTP 服务误把 `builder-debug.yml` 当成版本清单。修正为 `latest-linux.yml` 后重新启动旧版，完整自动更新通过；该问题属于测试辅助脚本，未修改应用更新逻辑。

自动重启后 CDP 端口受到子进程继承影响，无法继续通过原端口查询。因此改用 X11 只截取测试应用窗口，结合运行中挂载目录的版本、AppImage 哈希与后端健康检查完成独立交叉验证。升级成功不以调试接口是否可用为判据。

未覆盖：Windows、macOS；COS/GitHub 公网更新源的实包下载与回退；不同权限目录；跨架构更新；系统关机中断、网络故障或断电恢复。该机器不提供 macOS 或 Windows 环境，不能用本次结果代替它们的实机验证。

测试包及日志保留在远程 `/tmp` 工作目录供复核，应用与测试服务已停止。未修改目标机器的正式应用、其他程序或系统软件包。

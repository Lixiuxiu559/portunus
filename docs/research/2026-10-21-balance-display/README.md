# 余额展示语义与交互修正

2026-10-21。用户截图显示 DeepSeek 卡片没有金额，仅“数据已过期”和绝对时间。调查和实施只涉及余额状态呈现及卡片刷新，不读取真实上游凭据或发送真实查询。

> 后续状态：余额状态与卡片刷新随 `0b279e0` 提交；`e185701` 已恢复顶部导航，本文截图中的侧栏仅为当时验证画面。余额规则保持不变，当前入口见[使用说明](../../channel-quota.md)。

## 原因与 CC Switch 对照

Portunus 原 `backend/quota/view.go` 把正常成功记录也套用最大展示年龄：默认5分钟新鲜、10分钟后从 Snapshot 移到仅供详情的 LastSnapshot。前端只展示 fresh/stale，于是停止自动查询后即使没有错误也会丢掉主金额。此“过期”来自本地规则，不是 DeepSeek 账户或余额到期。

对照本地 CC Switch 源码（复用此前调查的仓库版本，不声称远端最新版）：

- `src/lib/query/queries.ts:193` 的 resolveDisplayUsage：正常 raw.success 返回成功结果，不对闲置成功记录按10分钟抹除；10分钟 keep-last-good 针对临时/网络失败后的保留，确定失败立即清空。
- `src/lib/query/queries.ts:253` 的5分钟 staleTime 控制查询缓存新鲜度，不能当作账户到期。
- `src/components/UsageFooter.tsx`、`components/quota/QuotaLines.tsx` 将余额作为主要信息，就地刷新、更新时间和详细说明分层。expiredLine 对应显式 invalid 数据/套餐，不是本地读取时间变旧。

## 调整后的规则

1. 最近查询成功且身份有效：金额继续显示原始查询值；超过新鲜期标记 stale，但只给“x分钟前”更新时间，不声称实时，也不叫账户过期。用户取消同样不算上游余额查询失败。
2. 查询临时失败：在原有失败保留窗口内保留上次成功金额并标明本次更新失败；超窗隐藏旧金额，详情仍可看历史。
3. 鉴权/权限/配置与Key变更：继续立即使旧身份快照失效，后续网络错误不得复活它。
4. 卡片金额优先，去重复品牌/状态/管理说明；相对时间的 title 保留完整查询成功时间；每来源可就地刷新，设置入口仍常驻。
5. GET 摘要仍只读缓存，不在打开页面或搜索时自动发 POST。刷新同源互斥，202轮询只读GET；配置变更/卸载取消并隔离迟到响应，HTTP错误不抹掉旧摘要。

## 测试设计与验证入口

- Go view 表驱动：正常成功12分钟/一天后仍有金额和原查询时间；临时失败9分钟保留、11分钟隐藏；鉴权及其后临时失败不复活；禁用和版本变化不显示旧值；0保留。
- 前端纯函数：分钟/小时/天、未来时间和非法时间文案；未知/零/无限仍按既有数值规则展示。
- 独立浏览器fixture：12分钟前的成功余额、0美元、鉴权失败、未配置；重复点击仅一次POST；在途旧GET不覆盖新查询；202后只GET轮询；失败保留金额与安全提示；明暗小窗口截图。

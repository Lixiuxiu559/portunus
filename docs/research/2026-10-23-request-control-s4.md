# 请求级尝试预算与累计首内容期限（S4）

> 后续决策：strict/legacy 转换策略配置及请求侧拒绝分支已移除。本文涉及策略开关的内容是阶段历史；当前统一保留诊断、沿用正常调用行为，安全边界始终执行，见[当前诊断模式](2026-10-23-protocol-diagnostics-only.md)。

## 行为与配置

本阶段给每个客户端请求增加一个 `gateway.requestControl`，从分组选路前创建，所有目标、普通重试和预算字段兼容重试共用。strict 仍默认 `legacy`。

| 配置 | 默认 | 范围 |
| --- | --- | --- |
| `proxy.max_http_attempts` | 4 | 一次请求所有显式 Client.Do 总和，流式/非流式均适用 |
| `proxy.first_content_timeout_seconds` | 120 | 流式从选路前至首次交付开始的累计期限 |
| `proxy.retry_count` | 沿用 2 | 每个目标的普通重试上限，仍受请求总预算约束 |
| `proxy.first_byte_timeout_seconds` | 沿用 60 | 单次等响应头和头后首内容等待窗口，与累计期限取先到者 |
| `proxy.stream_idle_timeout_seconds` | 沿用 120 | 交付后的静默期限，不因本阶段缩短 |

新增配置的零值恢复默认，负值在 Load 时拒绝。支持环境变量 `PORTUNUS_PROXY_MAX_HTTP_ATTEMPTS`、`PORTUNUS_PROXY_FIRST_CONTENT_TIMEOUT_SECONDS`。旧配置文件缺少字段时仍正常加载。累计首内容默认采用独立的 120 秒，保留慢上游和切换目标的余量；它不再随重试次数或目标数量相乘。

例如总上限 4 时，首次发送、预算字段兼容发送、一次普通重试和换目标发送合计已经用完，不能再发第五次。兼容重试不享有额外次数。一个目标内的 RetryCount 不变，但所有目标共享的请求上限具有优先级。正常一次成功和预算内的既有重试顺序不变；持续故障时等待和调用数量有意收紧。

## 发送与交付边界

发送的共同入口 `doRequest` 在构造请求后、`trace.begin` 和显式 `Client.Do` 前扣减预算并检查取消/累计期限。被预算或期限阻止的发送不产生 HTTP attempt；能力预检查、熔断跳过和候选遍历也不消耗 Do 次数。Transport 内部重发、重定向和供应商实际接收次数仍不属于该计数承诺。

累计计时从请求体基本解析后、查找分组和选路之前开始，覆盖所有目标的请求装配、连接、响应头、非成功响应体、兼容重试、role/created/usage/心跳等待。单次窗口更早到期时，仍按现有分类判断是否允许剩余预算内重试，累计计时不重置。非流式仍用现有每次读完整响应的 timeout；本阶段未将其迁为跨目标总 deadline。

控制器使用可撤销计时器和取消 cause，不能用一个永久 context.WithDeadline 套住整条长流。交付门开始首次写头/帧前，与累计到期在同一锁内裁决：到期先发生则禁止交付；交付先发生则撤销累计计时器，保留客户端取消、现有 idle watchdog 和终态尾部窗口。之后禁止再通过该控制器发起 Do，沿用 S3 的交付后禁止重放规则。

## 失败与记录

总次数用尽为 `attempt_budget_exhausted`（502），累计首内容到期为 `first_content_deadline`（504），两者 StopRequest，不喂渠道熔断。父请求取消仍保持客户端取消归因；单次供应商超时/HTTP 错误沿现有分类。统一分类由 `failSpec` 维护。

每次真实 Do 仍恰有一条独立 attempt 记录；已完成的兼容失败先完成其记录，再竞争下一次发送许可。若外层在两次 relay 之间发现上限，最后的失败响应和服务日志说明请求级停止原因，不额外伪造一个 relay/HTTP attempt。旧 relay 日志仍描述已执行的 relay，不能把最后一条行内状态当作整个请求的最终凭证。

## 验证设计

- 总次数跨目标共享，含预算字段兼容重试；上限 1 时不能发送兼容第二次，也不能换家补次数。
- 预检查、熔断和发送许可拒绝不生成额外 HTTP attempt；所有实际 Do 保持序号/结束记录配对。
- 第一目标等待后第二目标只能使用剩余累计期限，响应头、metadata、兼容响应体均不能绕开。
- deadline 与首次交付竞争；交付前到期停止，成功交付后长流可超过原 deadline。
- 父请求取消、请求预算、累计 deadline 不作为渠道健康失败；已有供应商失败不能因此被清零。
- 新增配置缺失/零值/显式设置/环境覆盖/负值及 strict 默认行为。

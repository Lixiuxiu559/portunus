# Portunus 设计风格

版本：1.1｜日期：2026-10-20｜状态：资源页面、调用记录、设置与弹窗两轮统一已实施。

本文以撤回上一轮整体紧凑化之后的界面为基线，保留已单独完成的“访问范围”单行切换。用户已确认保留视觉身份、舒适偏紧凑、逐页验证三个方向。第 2、3 节记录统一前的现状；第 5 节作为实施规范，具体尺寸按组件角色和页面验证落实；第 9、10 节记录实际交付范围。

产品职责以 [PRODUCT.md](./PRODUCT.md) 为准。本文负责视觉、布局和交互的一致性；不改变路由策略、协议转换、数据或配置。

## 1. 已确认的风格定位

**温润玻璃感的桌面工具：柔和、清晰、有层次，操作适度紧凑。**

保留 Portunus 的暖色与玻璃质感，在同一套视觉语言中改善信息组织。以原有桌面界面为起点，保持导航、卡片、按钮、浮层之间的连续性。

五个关键词：

| 关键词 | 在界面中的含义 |
|---|---|
| 温润 | 暖白背景、橙色强调；深色使用蓝灰背景与较柔和的橙色 |
| 柔和 | 圆角、细描边、低对比度分隔、柔和阴影 |
| 通透 | 背景氛围与磨砂层次可感知，内容始终清楚 |
| 清晰 | 名称、来源、状态、动作具有稳定位置与层级 |
| 适度紧凑 | 消除结构浪费，保持可读文字和可操作的点击区域 |

这里的“玻璃感”描述本项目现有视觉语言。源码含 Liquid Glass 命名，不代表已经符合或经过任何外部设计规范认证。

## 2. 原来的设计是什么

### 2.1 配色：暖色浅色主题、蓝灰深色主题

浅色不是纯白：背景与表面带很浅的暖粉色相。橙色用于主操作、选中项和链接；灰褐色文字与背景保持一致的色温。底部大尺寸模糊色块提供暖橙、紫粉等环境色。

深色以蓝灰为底，提高正文和辅助文字亮度，降低背景色块的饱和度与亮度，并调整玻璃高光。它具有独立的颜色映射，而不是简单反相。

当前主要颜色来源：`index.css` 的语义 token。

| Token | 浅色当前值 | 深色当前值 | 用途 |
|---|---|---|---|
| `--accent` | `oklch(57% 0.20 48)` | `oklch(74% 0.15 48)` | 强调与选中 |
| `--background` | `oklch(97.02% 0.0088 34.39)` | `oklch(20% 0.02 265)` | 页面背景 |
| `--surface` | `oklch(100% 0.0044 34.39)` | `oklch(25% 0.02 265)` | 内容承载面 |
| `--muted` | `oklch(52% 0.015 34.39)` | `oklch(76% 0.015 265)` | 辅助信息 |

### 2.2 材质：磨砂、边缘高光和软阴影

顶栏、普通卡片、按钮、浮层分别有不同的透明度、模糊和阴影。导航包含胶囊选中面、细高光与流动过渡。弹窗的表面更实、更突出，以保证表单可读。

这套材质构成了原界面的辨识度。卡片里的输入、代码、列表等内容区更稳定，不应让背景穿透影响阅读。

### 2.3 形状：圆润的容器与胶囊控件

顶部导航、操作按钮、标签偏胶囊形；卡片使用较大的圆角，字段和小操作使用较小圆角。当前分组卡为 18px 圆角，接入面板常用 16px，字段 token 为 16px，图标按钮为 8px。

原有语言并非所有组件同一个圆角，而是“容器较舒展，小控件更利落，导航与按钮更圆润”。

### 2.4 字体：界面字体与技术文本分工

- 拉丁正文和数字使用 Inter；中文使用系统字体回退。
- 模型 ID、URL、代码等技术文本使用 JetBrains Mono。
- 页标题当前主要是 20px；说明主要是 14px；卡片名称存在 15px 与 18px 两档；辅助信息多为 11–12px。
- 标题以字重和位置建立层级，没有使用大字号营销式标题。

### 2.5 布局：桌面顶部导航、卡片资源、独立内容面板

- 顶栏高 56px，居中六项导航，左侧品牌，右侧主题切换。
- 主内容有 24px 外边距，最大宽度约 1280px，宽屏不会无限拉伸。
- 分组以两列卡片呈现；上游渠道、上游模型使用响应式卡片网格。
- 接入页分为连接配置与示例；记录页使用适合逐行比较的数据表格。
- 编辑渠道和分组沿用从卡片展开的浮层，保持操作来源可辨认。

### 2.6 动效：轻微反馈与液态导航

当前页面进场为 240ms 淡入与轻微上移；导航滑动约 620ms，叠加拉伸和点击涟漪；按钮悬停上移 1px。背景缓慢漂浮。已有多处减弱动态效果的适配。

这些动效具有连续、柔和的方向，不适合再混入另一套明显不同的弹跳或快速闪烁效果。

## 3. 当前问题：风格已经存在，执行还没有完全统一

| 观察到的问题 | 原因判断 | 后续处理方向 |
|---|---|---|
| 分组卡、渠道卡、模型卡的密度差异明显 | 内容结构不同，标题、内边距和底栏各自定义 | 先统一结构层级，再按内容调整间距 |
| 上游模型仅名称与渠道，却占较大面积 | 展示信息较少，仍沿用通用卡片体积 | 先尝试卡片内同行组织和减少空行，保留卡片风格 |
| 分组标题、策略、状态分散 | 元信息占用多层垂直空间 | 先做一张卡片样稿，确认哪些信息可以合并 |
| 不同页面的按钮大小和工具栏对齐不同 | `sm`、`md` 与手写样式混用 | 同类动作建立统一尺寸和位置规则 |
| 局部手写组件与 HeroUI 材质不同 | 分组卡和接入面板未完全复用全局卡片样式 | 统一材质参数与语义，避免简单套同一透明度 |
| 圆角与字体存在多组相近数值 | 随页面演进局部调整，缺少角色规范 | 建立按角色使用的有限档位 |

以上是源码与现有页面的观察。可读性、性能或对比度是否达标仍需专项测量，不能仅凭使用了语义 token 或玻璃注释就认定已达标。

## 4. 上一轮整体紧凑化的问题

上一轮同时进行了背景实色化、导航形状调整、卡片材质调整、字号缩小、模型卡片改表格和页面宽度调整。它改变了多个决定整体观感的因素，超出了局部消除留白的范围，用户已明确要求撤回。

由此确定后续方法：

1. 布局密度、视觉风格、组件形态分别讨论，避免一次同时改变。
2. 保留已存在的品牌特征，先处理重复状态、无信息空行和不合理拉伸。
3. 卡片转表格属于信息展示方式变化，需要单独比较样稿。
4. 先验证一个代表性页面，再推广到其他页面。
5. 不把“能在一屏展示更多内容”当作唯一成功标准。

## 5. 统一规则

本节作为后续统一的设计基线，逐项实施与验证，不追溯宣称现有页面已经全部符合。

### 5.1 配色与材质

- 沿用当前明暗主题与语义 token，不重新更换主色。
- 背景氛围保留；正文承载面必须稳定，装饰色不能压过文字与选中状态。
- 顶栏、导航、弹窗承担较明显的玻璃层次；重复铺排的内容卡使用较克制的玻璃效果。
- 输入框、代码区、表格内容保持足够实的底色。避免玻璃层叠玻璃层造成浑浊。
- 悬浮弹层可以比普通卡片更有阴影；大量平铺卡片不统一增加大阴影。
- 橙色优先用于主动作、选中与链接；错误使用危险色；配置完整性不能用视觉暗示为上游在线。

### 5.2 形状与尺寸

| 角色 | 建议基线 | 使用说明 |
|---|---|---|
| 页面外边距 | 24px | 沿用现有桌面骨架，窄窗口按实际需要减少 |
| 内容容器圆角 | 16–20px | 普通卡片与面板同一档，不随页面任意换风格 |
| 字段圆角 | 12–16px | 保留柔和形状，按单行/多行内容区分 |
| 小型分段控件圆角 | 8–12px | 如访问范围，外壳与选中项嵌套自然 |
| 导航、按钮、短标签 | 沿用胶囊语言 | 共享形状，不强行改成直角工具条 |
| 常规卡片内边距 | 16–20px | 内容少时优先减少结构层数 |
| 卡片之间 | 16px | 保留对象之间的边界与呼吸感 |
| 同组控件间距 | 8px | 标签与输入、操作按钮应有明确关联 |
| 单行控件高度 | 紧凑约 32px，常规约 36px | 同一工具栏同高；不以缩小点击区域换密度 |

这些值用于缩小选择范围，不要求立即全局替换。具体数值用样稿确认，优先复用组件变体与现有 token。

### 5.3 字体层级

- 页标题保持 20px，正文保持 14px。
- 普通卡片标题建议以 16px 为基线；分组服务名等角色允许保留 15px，最终通过并排样稿确定。
- 说明与元信息优先使用 12px。11px 只用于少量次要标注，关键状态和主要操作不依赖极小字。
- 技术标识用等宽字体；不把整页中文说明改成等宽字体。
- 长名称截断时保留完整查看方式；不能仅为放入一行不断缩小字体。

### 5.4 卡片、列表和表格

形式由用户要完成的任务决定：

- 分组是独立服务对象，卡片继续作为默认形态。名称、策略、成员、当前项、动作的位置应稳定。
- 渠道是连接对象，卡片继续承载名称、协议、地址及同步/编辑/删除。
- 上游模型本轮以现有卡片为基线。先优化卡片结构；是否增加列表视图留作单独设计，不默认转表格。
- 调用记录需要逐行比较时间、状态、耗时与用量，沿用表格。
- 设置采用分区与设置行；服务接入沿用连接参数与指南分区。

统一风格不等于所有页面都使用同一种容器。相同的名称、状态、来源与动作，应使用一致的视觉角色。

### 5.5 “紧凑”的判定

优先减少：重复状态文字、只有一个动作却单独占据的大区域、无内容的固定高度、无信息的重复标签、层层叠加的 margin 与 padding。

应当保留：对象之间的间距、组内与组外的差别、名称与来源的层级、可点击区域、正文行高、关键影响说明。

已经完成的访问范围单行控件可以作为局部优化参考：标签与操作同一行、状态由选中项表达、按钮不强行铺满整列。它不是把所有表单都压成一行的模板。

少量数据时保持自然内容高度；大量数据时明确滚动区域。不能靠虚构字段、重复信息或装饰统计填满页面。

### 5.6 操作与反馈

- 页头主动作使用橙色主按钮；同一操作区域主次分明，不把刷新、删除都做成主按钮。
- 图标按钮沿用统一 `IconButton` 的提示、焦点和危险态；破坏性操作保留确认与影响说明。
- 分段控件必须能分辨选中、悬停、禁用与保存中，不能只依赖颜色。
- 弹窗、下拉、列表与卡片具有同一套材质和间距关系。下拉长选项可读，弹层不能超出窗口。
- 操作说明靠近相关控件，长篇指南可折叠；理解操作所必需的影响不能只藏在悬浮提示里。

### 5.7 动效与可访问性

- 保留现有导航、卡片展开和主题切换的风格。时长是否调整独立评估，不与密度调整捆绑。
- 加载、保存、错误反馈及时显示；动效不能延迟功能生效。
- 尊重系统减弱动态效果；不新增无意义的持续动画。
- 保留键盘导航、可见焦点、拖拽的键盘替代和语义标签。
- 检查明暗主题的正文、辅助文字、选中状态与浮层对比度。用真实长名称和中文内容验证。

## 6. 后续页面调整顺序

| 顺序 | 内容 | 方式 |
|---|---|---|
| 1 | 明确本文件的风格方向 | 先确认保留的特征与可调整的部分 |
| 2 | 一个分组卡片与一个模型卡片 | 使用相同数据，展示原版与局部优化样稿 |
| 3 | 单页落地 | 检查小窗口、明暗主题、长名称、空态与多项数据 |
| 4 | 推广已验证规则 | 统一按钮、间距、状态与浮层，而非重新设计全部页面 |

每次变更说明具体改善了什么，使用同一视口与数据比较。保留可回退版本；样稿不得调用收费上游或更改真实配置。

## 7. 已确认的设计方向

用户已确认保留三项基线：

1. **视觉身份**：暖色浅色主题、蓝灰深色主题、橙色强调、磨砂玻璃、柔和圆角。
2. **页面骨架**：居中胶囊导航与现有内容宽度，分组/渠道/模型继续以卡片为起点。
3. **信息密度**：舒适偏紧凑，先整理结构，再调整尺寸。

背景强度、玻璃透明度、具体字号和卡片排版仍可在同一风格内微调。当前撤回动作不能被解释为用户已经认可原界面的所有细节。

## 9. 首轮实施：资源页面

本轮采用串行实施，先比较原版与新卡片的同视口模拟数据截图，再检查其他资源页。

- 新增 `resource-style.css`，集中维护资源页页头、动作区、卡片间距、标题、技术名称、来源文字与下拉宽度。
- 分组、渠道、模型和接入页复用页头排版；标题仍为 20px，说明仍为 14px，页头主要操作保持常规胶囊按钮。
- 模型保留三列/两列响应式卡片，将模型名与所属渠道组织为同一个身份区域，使用与分组相同语言的图标底座。模型名为 14px 等宽字体，来源为 12px；卡片内边距 16px，圆角 18px，间距 16px。
- 分组保留两列、原有材质与独立策略状态行；成员数放在策略旁，删除每卡重复的“客户端模型名”说明，页面底部的 model 含义说明保留。辅助信息与主要行内操作采用 12px。
- 渠道复用资源卡片间距与 16px 标题；保留协议标签，地址直接显示，不重复添加 Base URL 标签。
- 保留背景、主题 token、顶栏、胶囊导航、玻璃材质、动效、内容最大宽度及现有功能。未修改后端、客户端配置、用户数据或真实监听范围。

验证：`pnpm test` 74 项通过，renderer 构建通过，`git diff --check` 通过。浏览器使用模拟数据检查明暗主题、长名称、1024 宽窗口无横向溢出，名称/渠道筛选、清除、分页、新增和删除确认、分组手动切换与键盘排序。未运行收费上游请求。样式调整未引入业务逻辑，因此未新增镜像测试，未运行复杂度或突变审计；已核对本轮独立 diff 与原有业务回调。

模拟页面中模型卡高度约 92px → 72px；这些数值仅描述本轮样本，不作为所有内容固定高度。

## 10. 第二轮实施：调用记录、设置与弹窗

调用记录与设置分别实施，随后与公共弹窗样式集成验证；未改变请求构造、统计口径、同步与更新逻辑。

- 调用记录复用页头，刷新入口位于页头右侧；统计卡采用 18px 圆角、16px 间距与等宽数字。筛选控件为 36px，间距 8px，保留日期选择、客户端协议、状态、名称与分组筛选。表格采用固定列宽，长技术名称省略并保留完整提示，横向滚动限定在表格中；分页不会被压出视口。
- 设置复用页头与分区卡片，设置行使用 14px 标签、12px 辅助文字和细分隔。版本信息与仓库链接适应受限宽度，更新说明可换行，保留同步、服务接入跳转、下载进度、更新重试与安装入口。

# macOS 独立更新验收设计

依据：用户要求首次手动放行后，通过应用自动完成后续更新；本次在临时应用副本验证，不覆盖正式安装和数据。

使用现有 Go testing、Node test runner 与本机真实 Electron/系统命令，不新增测试框架。

| 规则 | 场景及断言 | 验证方式 |
| --- | --- | --- |
| 只安装可信新版 | 正确 Ed25519 签名通过；ZIP 改字节、签名缺失、错误密钥、错误版本/架构、降级均拒绝，旧应用不变 | Go 单测、实际 helper |
| 解包不越界 | ../、绝对路径、反斜杠、重复路径、逃逸符号链接拒绝；Electron framework 内部符号链接可用 | Go 单测、真实 Electron ZIP |
| 替换前完成准备 | 解包、应用身份/架构、ad-hoc 签名、隔离标记处理失败均不退出旧版 | Go 单测、实际 helper |
| 等待退出 | helper 就绪后旧进程还存活时不改旧应用；退出超时保留旧版 | Go 单测、实际 helper |
| 原子替换并可恢复 | 同目录 staging，旧版备份后 rename 新版；替换或启动失败恢复旧版；成功启动并收到正确 token 才清理备份 | Go 单测、真实 Electron fixture |
| 启动成功才确认 | 实际产品须后端 ready 且 React 页面成功提交，通过受限主 frame IPC 确认；错误 token/版本/目标路径不写确认文件 | Node 单测、真实 Electron fixture |
| 保持原有入口 | COS/GitHub 同版本回退保留；准备完成才发 downloaded；异步安装失败恢复可重试状态；Dev 不启用更新器 | Node 单测 |
| 发布链完整 | ZIP 签名与内置公钥匹配，CI 缺密钥明确失败；签名随包上传 COS，签名失败不发布清单 | Node/Go、Python 单测及签名脚本实测 |

真实 Electron fixture 验证原生进程启动、隔离属性、替换与回滚，不等于实际正式版完整升级验证。未覆盖系统版本差异、只读/需提权安装目录、断电/系统崩溃恢复和真实 COS 发版。安装器不提权，不写用户数据目录。

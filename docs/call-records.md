# 调用记录与排障

调用记录用于查看选中的渠道、模型、用量和错误，以及同一请求中的重试与切换过程。Portunus 不配置模型价格或计算费用，实际费用以供应商账单为准。

## 从一条异常记录开始

1. 打开“调用记录”，按时间、分组、渠道、模型、协议或结果缩小范围；已知请求 ID 时使用精确匹配。
2. 打开记录详情，查看请求 ID、渠道 ID、实际模型、协议、耗时和错误摘要。可复制请求 ID 和错误；渠道名称来自当前配置，历史归属以记录中的渠道 ID 为准。
3. 切换“按请求归并”，查看同一请求 ID 关联的日志。没有请求 ID 的历史记录每行独立保留。
4. 在详情的“上游尝试链”中查看重试原因和顺序。每页 20 条，可翻页、刷新；查询失败时可重试，尝试错误也可单独复制。

“日志记录”按持久化日志行分页，“按请求归并”由服务端关联后分页，不只合并当前页。关联项详情展示最近一条持久化日志和已采集尝试，没有列出全部关联日志行；需要逐行核对时，可用请求 ID 筛选“日志记录”。

## 如何理解数字和结果

| 内容 | 当前含义 |
| --- | --- |
| 记录数和用量统计卡 | 按符合筛选条件的日志行统计；同一客户端请求可能因重试或切换产生多行 |
| 归并项数 | 相同非空请求 ID 合并后的关联项，加上无 ID 的独立历史行；不是准确客户端请求数 |
| 关联日志数 | 该关联项的全部持久化日志行数，可大于当前筛选命中的行数 |
| 最近日志结果 | 最近写入日志的结果；不证明客户端请求最终成功或模型正常结束 |
| 已采集尝试数 | 应用显式发起的 HTTP 调用尝试，包括连接失败和取消；不等于上游实际收到的请求数 |
| 尝试处理成功 | 这条尝试的处理结果；不等于完整请求最终成功 |

筛选只决定是否选中关联项，摘要包含该请求的全部日志。例如同一请求先在渠道 A 失败，随后切换 B 成功：筛选“A 渠道 + 失败”仍会显示该关联项，其最近日志可能是“B 渠道 + 成功”；统计卡仍只统计符合筛选条件的失败日志。这是两种查询口径，不是筛选失效。

最近日志按写入 ID 选取，列表中的最近时间、渠道、模型和结果来自同一条记录。关联日志的最早、最晚时间描述时间范围，回填历史数据时可能与写入顺序不同。

## 尝试链能说明什么

| 原因 | 含义 |
| --- | --- |
| 首次调用（initial） | 请求的首次显式 HTTP 尝试 |
| 同目标重试（retry） | 对当前目标再次尝试 |
| 切换目标（failover） | 转向后续目标 |
| 预算兼容重试（budget_compat） | 调整输出预算字段后的兼容尝试；记录字段名，不保存字段值 |

普通重试和目标切换可产生多条旧日志；预算兼容重试独立记录在尝试链中，不额外增加旧日志行，也不重复累加 token。

- 没有请求 ID：无法关联尝试链。
- 没有已采集尝试：可能未采集、未发起或记录缺失，不能据此认定实际调用为零。
- 序号存在缺口：记录可能不完整。
- 序号连续：完整性仍未确认，请求可能还在进行或尾部记录缺失。

当前没有请求终态和采集完整性凭证，因此不能从日志或尝试链计算准确的最终请求成功率。尝试记录也不逐一统计 HTTP Transport 内部重发或自动重定向产生的物理发送。

## 留存与分享

历史日志不会回填未知尝试。日志保留天数同时用于清理日志和尝试记录；设为 0 时禁用自动过期清理。日志按记录时间、尝试按开始时间清理，每小时执行一次，因此旧请求的关联信息可能逐步减少。

记录不保存完整提示词、请求/响应正文、上游 URL 或鉴权头，但截断的错误摘要可能带有上游返回片段。分享诊断内容前，检查错误文本是否包含敏感信息。

## 验证范围

请求归并、筛选口径、长尝试链、缺口提示、复制和窄窗布局已通过[隔离浏览器与管理 API 验证](research/2026-10-21-request-associations/README.md)。独立尝试记录另有[实际 main 进程与本地合成上游验证](research/2026-10-21-upstream-attempts/README.md)。这些日志功能验证不等于桌面安装包或外部收费上游验证；Responses 的真实上游验证见[工具与双轮会话报告](research/2026-10-20-responses-tools-multiturn/README.md)。

## 网关切换诊断

日志详情中的“网关切换诊断”独立记录候选跳过、半开名额、固定备用选择及停止原因。跳过不构成HTTP尝试，不增加旧调用或用量统计。事件最多保留256条，截断数明确展示，最终摘要独立保留；无诊断表示可能未采集、尚未结束或已清理，不能推断没有跳过。交付表示开始尝试写模型响应，不证明客户端完整收到；网关结束结果不用于计算客户端最终成功率。详见[实施说明](research/2026-10-23-routing-diagnostics.md)。

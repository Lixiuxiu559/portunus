## 术语与概念

### 资源关系

| 对象 | 当前含义与关系 |
|---|---|
| 渠道（Channel） | 一个已保存上游连接的地址、协议、凭据与选项；渠道到模型为一对多。 |
| 上游模型（Model） | 归属某渠道的本地资源条目。相同模型名在不同渠道仍是不同资源；不是直接对外公开的模型。 |
| 分组（Group） | 聚合多个渠道模型的对外入口。`Group.Name` 是客户端请求中的 `model`。 |
| 分组成员（GroupItem） | 以 `ModelID` 引用模型，含优先级；`manual` 另以 `ActiveItemID` 指定当前成员。 |
| 查询来源（quota.Source） | 某渠道独立的账户余额/额度查询配置；不是生成连接，也不改变路由。 |

```text
渠道 1 ── N 上游模型 N ── N 分组 1 ── N 分组成员
  │                                │
  └── 0..1 独立余额查询来源        └── 分组名 = 客户端 model
```

### 路由与协议

- `manual`：只解析激活成员；没有有效激活成员会报错，不因失败自动换成员。
- `failover`：按成员 `priority`、成员 ID 升序返回候选，符合处置条件才顺延；不是按权重或动态评分选路。
- 客户端与上游协议不同才进行语义转换；同协议保留原生载荷。跨协议支持不意味着所有供应商、模型或扩展能力等价。
- `/v1/models` 返回非空分组，跳过没有成员的分组；非空不证明分组已验证可调用。

### 凭据和访问边界

| 凭据/接口 | 用途与限制 |
|---|---|
| 渠道 Key | 调用上游模型，保存在渠道配置；管理响应对其脱敏。 |
| Portunus API Key | 客户端调用 `/v1` 的令牌；支持命名和稳定 ID，不能据此访问 `/api`。 |
| 余额查询 Token | 独立的只读查询凭据，可按适配器选择继承渠道 Key；不默认等于模型调用令牌。 |
| `/api` 管理面 | 要求真实 TCP 对端为回环地址，并校验本机 Host 与允许的 Origin；不信任转发头。 |
| `/v1` 服务面 | API Key 鉴权；桌面默认本机监听，明确启用 LAN 后可监听 `0.0.0.0`。 |

本机进程属于管理信任边界；本机反向代理不能作为向远端公开 `/api` 的授权机制。

### 用量、余额与观测计数

- **日志行**：`shared.Log` 的持久化记录。普通重试和目标切换可让一个客户端请求产生多行；保留 token 与缓存用量。
- **关联项**：非空 `request_id` 的日志归并结果；无 ID 历史日志逐行独立。关联项数不是准确客户端请求数。
- **显式 HTTP 尝试**：`UpstreamAttempt` 记录应用调用 `http.Client.Do` 的尝试，包括预算兼容重试；不等于上游实际收到数或 Transport 物理发送数。
- **切换诊断**：`RoutingTrace` 保存候选跳过、准入、停止原因等元数据；不是客户端完整接收凭证。
- **余额/额度**：独立上游账户查询的缓存观测，不与 token 用量、调用费用、路由健康或跨账户总额混同。

未知、零和无限必须区分；缺少 usage 不代表没有消耗。没有请求终态和采集完整性凭证时，不从最近日志、连续序号或空尝试列表推断最终成功率或零调用。

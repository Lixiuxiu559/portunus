## 用途与边界

`quota` 独立管理上游账户的只读余额/额度查询，不参与模型生成、路由、熔断、token 聚合或费用计算。一个渠道对应一个上游账户，只允许一个查询来源；重复创建返回 409，多账户应分别建渠道。

`main` 注入事务内渠道凭据读取函数。`api` 只做管理 HTTP 适配；适配器构造请求和解析响应，`Service` 协调配置版本、互斥、缓存和调度；前端展示标准条目，不自行解析厂商原始响应或计算跨币种合计。

当前注册表包含 DeepSeek、硅基流动中国站、OpenRouter、NewAPI 和结构化自定义查询。自定义来源通过声明式 GET/POST、JSON Pointer 和精确十进制换算提取字段，不执行脚本、OAuth、登录或多步流程。

## 主要流程

### 读取与主动查询

```text
打开卡片/列表 → GET 缓存摘要（不主动访问上游）
草稿测试 / 刷新 / 保存并查询 → POST 明确触发一次只读查询
启用且间隔非零 → 后台调度按计划查询
```

- 草稿测试不保存来源或快照；保存本身不主动查询，但已经启用的后台调度仍可能执行。
- 单来源只允许一个在途任务，全局最多两个查询执行槽；重复操作返回进行中视图，通过只读 GET 获取后续结果。
- 网络位于配置事务外；写回再次核对来源身份和 `config_revision`，修改、禁用、删除及继承 Key 变化会取消并隔离旧任务。
- 更新使用 `expected_revision` 乐观锁。读取凭据只返回是否存在，不返回 Token。

### 成功、失败与身份变化

正常成功快照保留真实成功查询时间，闲置较久不自动称为账户过期。临时失败只在上次成功起算的保留窗口内展示旧快照；鉴权/权限或配置身份失效后，旧身份余额不再作为当前值展示。未知、真实零、无限和部分缺失分别表达。

NewAPI 的钱包、订阅和套餐名称是不同查询部分。钱包为零不证明无订阅；局部接口失败时不能把缺失额度当成零。后端先聚合原始额度再换算，含不限额订阅时不伪造有限合计；限流冷却按相关接口最长等待处理。

### NewAPI 单位自动识别

`POST /api/quota/newapi/detect` 调用 `Service.DetectNewAPIUnits`：

1. 校验站点根地址并取得查询执行槽，设置 20 秒期限。
2. 不带查询 Token，读取公开的 `/api/status`；不加载凭据、不保存来源、不查询账户余额。
3. 读取明确的 `quota_display_type` 和汇率参数，支持 USD、CNY、CUSTOM、TOKENS（原始 QUOTA）。
4. 只有用户明确采用识别结果，前端才替换手动配置；失败或不完整时保留手动配置，不猜币种或倍率。

人民币/自定义单位按站点汇率换算；每展示单位额度支持正数和精确分数，避免提前舍入中间倍率。仅有旧式 `display_in_currency` 不能唯一确定币种。

## 待确认项

1. 各 NewAPI 部署版本的公开状态字段和账户接口可能不同；识别失败必须保留手动配置。
2. 汇总不证明实际扣费顺序或每个模型请求均可使用对应额度；实际费用仍以供应商账单为准。
3. 余额历史曲线、脚本化自定义查询、OAuth 与厂商套餐专属适配不是当前能力。

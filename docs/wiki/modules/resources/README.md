## 用途与边界

这些模块把“上游账户连接”和“可调用的模型资源”组织成稳定的分组入口。厂商预设只用于新建或显式应用时展开默认值，运行时从已保存渠道快照打开连接，不按域名推断厂商，也不重新套用预设。

- `channel` 保存连接及限流/并发设置；管理响应对 Key 脱敏，编辑时空 Key 表示保留。
- `upstream` 校验新连接、选择预设配置档，并用 `protocol.NewUpstream` 构造协议接入器。
- `model` 是归属渠道的资源目录；`group` 通过成员 ID 引用模型。
- `router` 只负责策略下的候选解析；实际重试、限流、熔断、并发准入和 HTTP 调用属于网关。

## 主要流程

### 新建/编辑连接

```text
草稿字段 → upstream.Resolve 展开并校验配置档
→ 保存 Channel 快照 → 同事务导入本次选择的模型
```

Base URL 是 API 根地址，可包含所需版本或部署前缀；新配置拒绝 URL 凭据、query、fragment 和具体操作路径。`upstream.Open` 为旧渠道保留原端点拼接行为，不把新建校验强行套到所有历史配置。

渠道保存只新增选择的模型，不隐式全量同步。渠道和本次模型导入在一个管理事务内，模型导入去重并保留已有模型 ID。模型预览和连接校验不证明生成权限或调用成功。

### 模型发现与同步

- API 模式通过已保存连接获取模型列表；manual 模式不支持模型发现。
- 手动或定时同步获取全部发现项，只导入本地缺失的 `(channel_id, name)`，不覆盖既有条目，也不删除上游已消失的模型。
- 自动同步跳过未启用自动同步或手动发现的渠道；单渠道失败不阻断其他渠道。
- 同步不发送模型生成请求；主动调用验证是另一项由用户触发的操作。

### 分组与路由候选

| 策略 | 当前解析规则 |
|---|---|
| `manual` | 空组报错；查找 `ActiveItemID` 对应成员，找不到则报未指定激活项，只返回一个目标。 |
| `failover` | 复制成员后按 `priority`、成员 ID 升序，逐个解析为“模型 + 渠道”并返回全部候选。 |

创建分组可在一个事务中创建多个成员，并选择初始手动成员。`GroupItem` 的模型名、渠道 ID 是查询时关联加载的元数据，不是成员表的重复字段。当前 API 只接受 manual/failover；旧策略迁移不应被理解为仍支持轮询。

主动调用验证复用正式网关的转发能力，但使用指定渠道和模型、隔离的日志与熔断状态，不切换到其他渠道；详见[渠道接入说明](../../../upstream-channels.md)。

### 删除与引用影响

删除前由 `GET /api/models/:id/deletion-impact` 与 `GET /api/channels/:id/deletion-impact` 提供只读预览：受影响分组、将移除的成员、手动激活项是否清除、分组是否变空；渠道另含模型数量与余额来源。预览不写数据。

确认后在同一事务内删除目标、引用它的分组成员，并清零指向这些成员的手动激活项；任一步失败整体回滚。分组与历史调用记录保留，最后一名成员移除后分组仍存在但为空，且不出现在 `/v1/models`；不自动选择替代成员。前端在预览加载失败时禁用确认，避免把“影响未知”当作“无引用”。

SYSTEM DESIGN / SPECIFICATION

密码学信封与文件格式1

文件扩展名 .portunus 仅用于选择提示；识别依赖magic、版本、长度和认证。此处是格式契约，不随机器CPU、应用版本或运行参数变化。

二进制文件布局
偏移长度／类型字段规范
0–78 bytesmagicASCII PORTCFG 后跟一个0字节；不是ZIP。
8–9uint16 BEenvelope_version固定1；密码学信封版本，不自动转换。
10–11uint16 BEformat_version固定1；必须与解密后的根字段一致。
12uint8kdf_profile固定1：Argon2id v0x13，m=65536KiB、t=3、p=1、输出32字节。
13uint8cipher_profile固定1：AES-256-GCM，nonce12字节，tag16字节。
14–152 bytesreserved必须为0，未知位直接拒绝。
16–3116 bytessalt每次导出用crypto/rand重新生成。
32–4312 bytesnonce每次导出重新生成，禁止复用；不由时间戳或密码计算。
44–47uint32 BEplaintext_len未加密UTF-8 JSON字节数，最大32MiB。
48–末尾P+16 bytesciphertext_and_tagGo AEAD.Seal返回值；文件总长严格等于P+64。

编码与解码顺序

  1. 编码：在只读快照结束后严格校验载荷，生成16字节salt及12字节nonce，按固定profile派生32字节密钥，以完整48字节header作为AAD调用AEAD.Seal。
  2. 解码：先限制文件总量，再验证magic、两个版本、profile、保留位、P及精确总长；这些检查不通过时不执行KDF。文件自带值不能指定任意内存、迭代次数或算法。
  3. 认证成功前不解析、不展示任何配置内容。错误密码与认证失败统一反馈“无法解密，请检查密码或文件”，不依据未认证内容生成有效预览。
  4. app_version只放在加密载荷内；文件声明不支持的版本可提前拒绝，但不能把未认证header称为可信来源信息。

密码使用原始有效UTF-8，1～1024字节；不trim、不做Unicode归一化，两次输入按原值一致。Main在UTF-8编码前拒绝JS字符串中的未配对代理项，不能通过替换字符偷偷改密码。非空是产品规则，不新增最低强度门槛。密钥、密码、明文均不落盘；清理可控byte buffer并释放引用，但不承诺Go／JS托管运行时能安全擦除所有副本。

选择Argon2id利用现有 golang.org/x/crypto v0.48.0，并将其作为直接依赖声明，版本保持不变。p=1是控制本地资源的项目取值，不能称为原样采用RFC9106的p=4配置；profile一经发布即固定。

设计约束
完整性与可用性分别处理

使用认证加密拒绝文件篡改；不设置固定密码、恢复后门或静默降级算法。空包、非法配置和格式不符都不能通过导入，正确密码也不能绕过这些检查。

目标名称集最多100000个渠道／组名称、原始名称字节总量≤64MiB逐行有界读取，只取名称。超过上限整次拒绝，避免无限读入目标命名空间。

名称计划

  1. 源渠道和分组各自按原名称检查唯一性，目标名称比较沿用SQLite现有BINARY唯一约束，不做locale折叠。
  2. 预先保留本文件的全部原名称，再为与目标冲突的对象生成名称，避免“A”的候选名挤占另一个本来可保留的源名称。
  3. 候选依次为“名称（导入）”“名称（导入 2）”…，使用满足16KiB限制的UTF-8前缀。每个命名空间最多探测100000个候选，超出返回NAME_SPACE_EXHAUSTED；不静默改用随机或覆盖。
  4. 计划记录每个渠道／组的原名、新名及ref。plan_sha256是固定字段顺序的Go结构JSON（file_sha256、channels的ref/from/to、groups的ref/from/to）的SHA-256。客户端把它视为不透明值，不自行计算。
  5. 确认时只核查已经显示的新名称是否仍可用，不因其他名称被删除而缩短或重新分配已确认名称。若已显示名称被占用，整次不写入，终结旧操作，并生成新预览／新operation_id供再次确认。

名称预算和Preview/Result序列化预算在写入前计算；结果过大、目标Schema不符合已核对的业务唯一约束、实际生成ID超过JS安全整数范围时，整次拒绝或回滚，不能交给现有页面处理有损编号。

展示预算算法

导出阶段先用源名称构造PreviewDTO主体，使用与正式响应一致的Go JSON编码；原名和计划名均先填源名称，has_key使用较长的false。要求 编码字节数 + 64×(渠道数+分组数) + 4096 ≤ 8MiB。64字节余量覆盖每个最终名称的最大导入后缀，4096字节覆盖固定长度标识、hash、时间及封装字段。Result的保守主体包含全部渠道和分组（即使实际渠道未改名）、两份原名和16位安全整数ID，按同样余量要求≤12MiB。这样不会导出本实现因显示预算而必然拒绝的包。导入仍按同一保守算法检查，并在实际计划与提交结果编码后各检查一次精确上限；预算不通过时不截断、不提交。

SYSTEM DESIGN / SPECIFICATION

导出与安全文件落盘

页面上的初始计数是摘要；真正导出的内容以只读事务取得的完整快照为准。

  1. 设置页从summary取当前计数；三类全0时禁用导出。服务端仍独立检查空库，不能只依赖按钮。
  2. UI校验两次密码一致后，由Main显示系统保存对话框。取消后不发起KDF或写文件。
  3. Go在同一只读事务中有界读取channels、models、groups和group_items全部快照，建立关联并检查完整性；结束读事务后才执行Argon2及加密，避免派生期间持有读锁。
  4. Go返回完整密文和绑定该快照的计数header。Main限制响应大小，完整接收成功后才写目标目录中的随机临时文件。
  5. 以wx／O_EXCL和0600创建临时文件，写完、同步、关闭后rename到所选目标。错误只清理本次创建的临时文件；成功结果显示实际导出快照计数。
设计约束
不把原子可见性当作断电保证

同目录rename保证支持平台上的原子替换语义；目录fsync按平台能力尽力执行。Windows的0600不能代替ACL隔离，目录权限由系统和用户选择的位置决定。真实断电恢复、平台文件对话框和替换行为列入实施后平台验收。

选择器给出的真实路径只留Main。导出目标若是目录、符号链接或不支持的特殊文件，返回明确文件错误并让用户另选；不跟随页面传入路径。导入也通过打开后的同一描述符fstat确认普通文件，并有界读取为不可变密文副本，之后不按路径再次读取。正常失败清理自有临时文件；崩溃残留也只能是密文，不扫描用户任意目录。

预览与恢复算法

  1. 准入后读取密文并做信封检查、派生及认证；严格解析和校验字段、关系、数量与能力。三类全0的空包拒绝。
  2. 生成不可变计划、Preview DTO与预算，生成UUIDv4 operation_id和随机preview_id；先写prepared纯元数据，再返回预览。预览原始载荷只留内存，记录owner_instance_id及期限。
  3. 确认绑定preview_id、operation_id、file_sha256、plan_sha256。已提交的同操作返回已存结果；终态aborted不能重新执行。当前进行中同操作返回202，并引导只读查询。
  4. 收到有效确认后，短写confirmed_at；业务事务的第一条数据库访问必须是条件DML claim，匹配prepared、owner、hash、期限与确认记录，并要求RowsAffected=1。不能先SELECT开启旧快照。
  5. 持有SQLite写锁后复核计划名称，按依赖顺序插入完整图，保存最终结果并更新committed，统一提交。遇到已占用名称回滚，不静默换名；终结旧操作并生成新预览供再次确认。
  6. 任何错误先回读同op回执；committed回放成功，能够条件fence成aborted才报告确定失败。若查询／fence也失败，返回RESULT_UNCONFIRMED，保留op并继续核实，不自动生成新op。

ResultDTO为 {operation_id,state:"committed",committed_at,result_version:1,counts,rename_count,channels,groups,replayed}。channels只含发生改名的 {ref,id,original_name,name}；groups含本次全部 {ref,id,original_name,name}，不重复保存成员／模型／连接信息。id为十进制字符串，写入仍检查其处于现有页面安全整数范围。终态DTO从回执还原，不按后来被用户改过的名称重建历史结果。aborted只返回固定failure_code、stage及零新增数量。

本功能HTTP接口不经过现有renderer request.js自动重试。Main只自动重试只读查询；提交超时／断线后先查询同op，绝不能自动新建预览或换operation_id再提交。轻量网络重试至多3次、间隔500ms；提交后的状态查询最多120s（1s后逐步到2s间隔），超出显示“结果待核实”，允许手动继续查询。

迁移与保留

新增 configtransfer.Migrate(db) 使用下列固定目标DDL，在既有业务AutoMigrate之后、迁移服务开始接收请求之前执行。它只创建这张表与两个索引；启动检查已存在表的字段、PK及索引符合本基线，不擅自修复未知Schema。已有业务唯一约束不符时停用迁移功能并报UNSUPPORTED_DATABASE_SCHEMA。

CREATE TABLE IF NOT EXISTS config_import_receipts (
  operation_id TEXT PRIMARY KEY NOT NULL,
  owner_instance_id TEXT NOT NULL,
  file_sha256 TEXT NOT NULL CHECK(length(file_sha256)=64),
  plan_sha256 TEXT NOT NULL CHECK(length(plan_sha256)=64),
  status TEXT NOT NULL CHECK(status IN ('prepared','committed','aborted')),
  created_at_ms INTEGER NOT NULL,
  expires_at_ms INTEGER NOT NULL,
  confirmed_at_ms INTEGER,
  claim_started_at_ms INTEGER,
  committed_at_ms INTEGER,
  acknowledged_at_ms INTEGER,
  result_version INTEGER NOT NULL DEFAULT 1 CHECK(result_version=1),
  channels_count INTEGER NOT NULL DEFAULT 0 CHECK(channels_count>=0),
  models_count INTEGER NOT NULL DEFAULT 0 CHECK(models_count>=0),
  groups_count INTEGER NOT NULL DEFAULT 0 CHECK(groups_count>=0),
  rename_count INTEGER NOT NULL DEFAULT 0 CHECK(rename_count>=0),
  result_json TEXT,
  failure_code TEXT,
  failure_stage TEXT,
  CHECK(expires_at_ms > created_at_ms),
  CHECK(status='committed' OR (channels_count=0 AND models_count=0
         AND groups_count=0 AND rename_count=0)),
  CHECK((status='committed' AND committed_at_ms IS NOT NULL
         AND result_json IS NOT NULL AND failure_code IS NULL)
     OR (status='prepared' AND committed_at_ms IS NULL AND result_json IS NULL)
     OR (status='aborted' AND committed_at_ms IS NULL
         AND result_json IS NULL AND failure_code IS NOT NULL))
);
CREATE INDEX IF NOT EXISTS idx_ct_prepared_owner
  ON config_import_receipts(status, owner_instance_id);
CREATE INDEX IF NOT EXISTS idx_ct_unack_confirmed
  ON config_import_receipts(created_at_ms DESC, operation_id DESC)
  WHERE acknowledged_at_ms IS NULL AND confirmed_at_ms IS NOT NULL;

prepared在预览返回前登记；取消、过期及启动恢复可以留下不含秘密的aborted元数据，这是回执范围，不属于残留的渠道／模型／分组。只列已确认且未ACK的恢复结果。终态与最小证明不按日志保留期删除，否则旧ID可能被重新执行。存储随用户有效预览／导入次数增长，不宣称固定空间；移除整个用户数据库或手工回退数据库后的证明连续性不在本功能保证内。

DDL的CHECK约束行形状与未提交计数，不单独阻止任意SQL倒转状态。单向生命周期由迁移包封装的条件更新保证：committed／aborted只允许从prepared转换且检查RowsAffected；ACK只更新终态的acknowledged_at，禁止无条件保存整个回执实体。此应用边界须有终态复用和回退拒绝测试。

旧版本应用会忽略新增表；回退应用时保留该表。已导入的配置属于用户数据，不能在版本回退中自动删掉。未来若变更本表或结果版本，另行制定增量迁移，不能覆盖现有终态。

事务、幂等、并发与启动恢复

最终写入只由Go完成。回执使“同一次确认”有持久身份；file hash只做绑定，不把文件重复导入变成去重同步。

-- BEGIN后第一条数据库访问；不能先SELECT开启旧读快照。
UPDATE config_import_receipts
SET claim_started_at_ms = :now
WHERE operation_id = :op AND owner_instance_id = :owner
  AND status = 'prepared' AND file_sha256 = :file_sha
  AND plan_sha256 = :plan_sha AND expires_at_ms > :now
  AND confirmed_at_ms IS NOT NULL;
-- 必须RowsAffected=1，随后复核显示过的名称并恢复完整配置图。
-- 所有INSERT、active_item_id映射、结果列和status='committed'在同一Tx。

-- 启动／恢复fence；同样先DML，不先读旧快照。
UPDATE config_import_receipts
SET status='aborted', failure_code='SESSION_LOST', failure_stage='recovery'
WHERE status='prepared' AND owner_instance_id <> :current_owner;

完整写入顺序

  1. 取得每op互斥和全局重活许可；已committed同hash立即回放，hash不匹配返回OPERATION_MISMATCH。aborted不再执行。当前同op运行中返回202，不启动第二个事务。
  2. 短写有效确认意图后，进入业务Tx并先claim。0行必须检查已存终态／期限或fencing，不允许继续创建配置。
  3. 按计划以显式列map写入渠道，序列化原始options；布尔false、数字0、空legacy字段都包含在列map里。不能直接依赖普通实体Create的默认值或调用会重套预设的CreateTx。
  4. 同事务内按唯一名称准确读回新渠道ID；按(channel_id,name)写入并读回模型；按唯一新名创建分组；逐组按文件items顺序创建成员并按(group_id,model_id)读回ID。此写法已隔离验证，不假定map能自动回填主键。
  5. 设置合法active_item_ref映射（null写0），保留原始priority；检查新ID与结果预算，然后同一Tx填充结果、计数、committed时间及状态。已有业务行不会更新。
  6. 错误先结束Tx并读回receipt；必要时通过条件DML把仍prepared的当前操作fence为aborted。只有终态依据明确时才给出成功或失败；查询／fence不可用时保持RESULT_UNCONFIRMED。

进程重启

新服务具有新owner。恢复DML与旧请求claim争抢同一SQLite写锁：恢复先成功，旧claim之后0行不能写；旧事务先持锁，则恢复等待结束后看到committed并不能把它改为aborted。该性质已在DELETE与WAL两种临时库模式、两独立连接池验证。

恢复尚未完成时，迁移服务ready=false，新增功能返回503；网关及原有管理功能可继续运行。恢复重试有界，DB_BUSY不等于名称冲突。当前实例运行中操作的recover与commit共用op锁；内存预览已丢失、已到期或旧owner的prepared才能被恢复fence。定时过期先释放秘密引用，再尽力持久化aborted；失效后即使状态短暂仍prepared也不能再claim。

SQLite驱动此基线的隔离实测为3.41.2，裸连接busy_timeout=5000ms、journal_mode=delete。设计不切换全局WAL或修改全应用连接池；DB_BUSY只在新边界做同op核实／有限重试。每次事务均使用请求上下文；取消或commit返回错误不能直接证明回滚。

导出表单／处理中密码与确认是UI短期输入；选择路径属于Main。密码不进入URL、持久化或日志；进行中防重复；取消选择不报失败。
选文件／校验file_token属于Main；password由UI输入；内容由Go校验。换文件使旧预览失效；非进行中关闭会释放令牌；认证错误保留文件供重输。
预览／名称变化PreviewDTO为Go冻结数据；详情tab、页码和折叠属于UI。按20项局部分页，成员显示通过ref派生；新名称计划需要再次确认，不能静默提交。
提交中／结果待核实opID与回执是权威；UI只显示短期请求状态。提交后断线显示正在核实，不报“已回滚”；只查同op。查询预算用完保留继续查询，不自动重新导入。
成功／已回滚终态ResultDTO来自回执，数量和最终名称不重新猜测。只在确定终态后清除输入与预览；用户关闭结果或查看分组后ACK。
恢复旧操作页面空闲时读取未ACK且已确认的摘要，再核实对应操作。复用成功／失败弹窗，标明上次操作时间；不在用户填写新表单时强行打断，也不创建新操作重跑。

PreviewDTO采用引用而非重复嵌入名称，最大8MiB；详情及改名列表本地20项分页，分组成员也局部分页，保持正常小数据原型不变。打开新弹窗、换文件、关闭或卸载时递增UI代次并取消页面等待；迟到的旧响应不能覆盖新状态。进行中关闭受限，但窗口被系统关闭／renderer重载仍由回执恢复。

IPC成功不会经过现有axios写拦截器，所以确定committed或回放committed后必须显式 responseCache.invalidate()，重取summary及相关列表；列表重取失败不推翻已经提交的结果。现有缓存generation可阻止先前慢GET写回旧快照。

“查看导入分组”使用现有 /groups 路由，附非持久导航state中的importedGroupIds，以String(id)匹配已刷新列表，提供“显示全部／返回配置迁移”。不创建生产新路由、不拼超长URL。若用户后来删除分组，历史结果仍表示当时提交成功，当前列表显示实际可见数量，不重建已删除对象。

失败语义与安全控制

新增边界使用结构化错误，不改变整个项目既有错误返回。HTTP错误形状为 {error,code,stage,retryable,field?,operation_id?,replacement_preview?}。

错误契约
错误码状态含义用户恢复
INVALID_INPUT / LIMIT_EXCEEDED400 / 413字段类型、大小、计数、编码、展示预算不符合；不显示原始字段值。修正输入或重新导出；无业务写入。
EMPTY_CONFIGURATION409三类全空，不导出空文件，不导入空包。先配置内容或选择其他文件。
FORMAT_UNSUPPORTED / CRYPTO_PROFILE_UNSUPPORTED422版本、profile或保留位不支持；不尝试转换／降级。使用支持该格式的应用或换文件。
DECRYPT_FAILED / FILE_CORRUPT422认证失败用通用解密提示；结构损坏可独立报不可读。保留文件或更换文件；不产生有效预览。
CONFIG_INVALID / SOURCE_INTEGRITY_ERROR422 / 409能力、字段或引用无效；以对象ref、字段路径定位。整次拒绝，不跳过问题项。
NAME_SPACE_EXHAUSTED / UNSUPPORTED_DATABASE_SCHEMA409 / 503名称探测预算耗尽，或实际Schema与要求不符。前者调整同名配置后重新预览；后者停用迁移功能，不能擅自修表。
PREVIEW_CHANGED / PREVIEW_EXPIRED409 / 410旧操作终结，不沿旧计划写入；新预览需确认。Main仍持文件时可重新解密；重启后重新选文件。
OPERATION_RUNNING / TRANSFER_BUSY202 / 423同op已有任务或全局重活槽占用，不排无限队列。前者查同op，后者保留输入让用户重试。
OPERATION_MISMATCH / OPERATION_ABORTED409op复用、hash不同或终态aborted，不允许执行。核实原结果；新的用户确认需要新预览。
DB_BUSY / TRANSFER_UNAVAILABLE / BACKEND_CHANGED503 / 503 / 409本机写竞争、恢复未就绪、实例不匹配；不能伪装成名称冲突。未提交阶段可重试；提交后先查同op。
RESULT_UNCONFIRMED503无法取得可证明的终态；不能说“已全部回滚”。保留op并核实；不自动创建副本。
FILE_READ_FAILED / FILE_SAVE_FAILEDIPC固定码只说明用户选择的位置／文件不可读写，不转发底层路径或错误原文。重新选择；正常失败清理自有临时文件。
安全约束
边界控制与验证落点
秘密与日志固定错误码／stage／ref路径；不返回解析器、SQL或文件系统原始错误。迁移DB会话使用Silent logger，禁止GORM慢SQL／错误SQL输出密钥参数。日志仅opID、阶段、码、数量、字节量和耗时。
IPC来源校验event.sender为主窗口webContents、senderFrame为主frame，并精确匹配当前file页面URL（忽略hash）或受控的http://localhost:5173开发origin。对入参做类型、长度和键白名单检查。
文件能力页面只传file_token／预览标识，不传路径、URL或任意文件内容。导航到新文档或renderer退出时失效令牌；原地hash导航不当作新文档。
环境绑定Main从runtime-profile/server-address和owned sidecar取得固定回环地址与instance/generation；调用前检查ready，响应仍核对实例。新路由的X-Portunus-Instance只是防误路由，不是鉴权。
资源准入Main在大读取前串行准入，Go在大body前占重活槽。Argon2没有立即取消能力，取消后仍等其真正结束再释放许可。秘密内存预算、响应上限、期限均独立实施。
持久化秘密回执、浏览器存储、应用配置和临时文件都不保存密码或明文载荷；只在Go的受限预览中短期保留原文，完成／关闭／到期释放。保留预算不是总内存保证。

2026-11-10实施契约补齐：错误允许可选field，表示固定字段名及数组下标构成的安全ASCII路径，长度≤256；Main只透传通过路径白名单的值，界面可据此定位字段，不透传底层异常原文或用户字段值。discard的preview_id改为可选，仅用于释放尚未预览的本窗口文件令牌；业务语义不变。

stage固定为input、body_read、snapshot、encrypt、decrypt、validate、plan、commit、recovery、file_read或file_save。终态aborted的failure_code可使用上述已知码，另有USER_CANCELLED（确认前取消）、SESSION_LOST（旧进程或预览丢失）和IMPORT_FAILED（已核实未提交的写入失败）；状态查询返回200的确定终态，不把它当作查询本身失败。retryable只表示同阶段可重试，不授权换新op；所有确认后的异常均先核实原op。

正式版和Dev只连接各自主进程拥有的sidecar与独立数据库。手工选择迁移文件只影响当前目标环境，不自动读取另一环境或复制数据库。设计和开发验收使用合成凭据，真实生成验证由用户另行操作。
